## 识图这边已经做好的

`vision.py`（`core.vision`）新增两个函数：

```python
part  = await vision.image_part(seg.data)                 # 一张图 -> {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}；取不到返回 None
parts = await vision.image_parts([seg.data, ...], limit)  # 几张依次取，最多 limit 张，取不到的跳过（不抛异常）
```

- 用的是看图时已经缩好的那份（长边 ≤ 1536 的 JPEG，小图和动图原样），刚 `describe()` 过的图不会重新下载。缓存只留最近 8 张，隔久了会重新下载一次。
- 太大、下载失败、不是图片时返回 None，这张就只给描述。不调模型，不改识图缓存。

`config.py` 新增两个开关，`.env.example` 里也加了：

| 参数 | 默认 | 说明 |
|---|---|---|
| `VISION_CHAT_SEES_IMAGE` | `false` | 回复这一轮把原图也给聊天模型看。测完再开 |
| `VISION_CHAT_MAX_IMAGES` | `2` | 这一轮最多带几张原图 |

自测：用假模型核对了：看过的图再取原图不重复下载、取出来能还原成图、坏链接和非图片会跳过、最多 2 张。程序测试 439 个通过，改前改后结果一样；另有 1 个 `test_napcat_forward_patch_script_1106` 在我这边的环境里失败，原因是缺 `tools\napcat_forward_patch.py`，和这次改动无关，改前也失败。

## 建议你这边怎么接

1. **记下这一轮的图**：`look_at_images()` → `rich_text(look=True)` 看图时，把这几条消息里的 image 段（含引用里的图）按顺序记到这一轮上，比如 `turn.image_datas`。高峰时段不看图（`look=False`），也就不带。
2. **拼本轮最后那条消息**：`_build_prompt` 里 `new_entries[-1]` 发给模型时，`cfg.vision_chat_sees_image` 打开、而且有图，就把 content 从字符串换成：
   ```python
   [{"type": "text", "text": 原来的文字}] + await vision.image_parts(turn.image_datas, cfg.vision_chat_max_images)
   ```
   只改发给模型的那份（`api_messages` 之后），**写进聊天记录的还是纯文字**。
3. **重说**：`_ask(turn, more)` 用的是同一份 `turn.messages`，带图会自动跟着。
4. **聊天规则补一句**（`prompts.py`）：大意是“这一轮你能直接看到图。图里画的是不是你，以描述里的说法为准（写着「伊蕾娜本人的画像」才是你，写着「画的不是你」就不是），别自己看着像就认”。原因：之前测过，DeepSeek 自己看图时，9 张别的灰发角色里有 4 张会被认成伊蕾娜；现在这一步由本机认人模型把关，结论已经写在描述里。
5. 空间评论、睡醒补回、主动冒泡先不带原图。
