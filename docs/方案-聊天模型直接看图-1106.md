# 方案：让聊天模型直接看图（11/06，识图 agent）

> 用户 11/06 说可以试：现在“识图模型写描述 → 描述交给聊天模型”分两步，麻烦，想让聊天模型直接看图。
> 聊天和看图用的都是 `deepseek-flash`（记忆整理才用 pro），所以聊天模型本身就能看图。
> 这份是**动手前的方案和测试点**，用户定了再做。

## 现在怎么走

1. 收到带图的消息，先进“收件箱”。确定要回了，`reply.look_at_images()` 调 `textin.rich_text(look=True)`。
2. `rich_text` 对每张图调 `vision.describe()`：本机认人 → `deepseek-flash` 写描述 → 拼成 `[图片：……]`。同一张图只看一次，结果存缓存。
3. 拼好的文字进聊天记录，再和人设、记忆一起交给聊天模型（`reply._ask`）。

## 两种做法

### 做法 A：这一轮带上原图，描述照写（推荐先试）

- 看图、写描述都照旧；**这一轮**问聊天模型时，最后那条消息除了文字，再附上原图（已经缩好的那份）。
- 聊天记录里照旧只存 `[图片：……]` 描述，下一轮就不再带图。
- 本机认人的结论照旧写在描述里（“伊蕾娜本人的画像”“画的不是你”），聊天模型看图时也看得到这句。

好处：她看得到原图，能自己结合上下文理解梗图、截图；聊天记录、长期记忆、空间这些要文字的地方都不受影响；出问题关掉开关就回到现在的样子。
代价：每张图多花一次聊天调用里的图片 token。按这几次测试的用量估算，一张缩好的图大约几百个 token，按空闲价约 0.0004 元一张。看图调用照旧要花。

### 做法 B：不再单独看图，聊天模型看图时顺便写一句图注

- 去掉单独的看图调用。聊天模型回复时，在末尾额外写一行图注（比如 `【图注：……】`），程序截下来存进聊天记录，不发出去。

好处：少一次调用，真正变成“一步”。
问题：
- 图注是她以伊蕾娜的身份写的，会带语气、会出戏，也不好控制长度；格式漏出去就会被发到群里。
- 同一个表情包每次都要重新付图片 token，现在是看一次就缓存。
- 她决定不回（`[不回]`）、群里旁听的图，就没有图注了。
- 截图要抄全原话、实物要写明人偶这些规矩，都得搬进聊天提示，聊天提示会变长。
- 改动大，几乎都在聊天 agent 的文件里。

**建议先做 A。** A 测出来回复明显更好，再看要不要往 B 走。

## 做法 A 要改哪里

| 文件 | 归谁 | 改什么 |
|---|---|---|
| `vision.py` | 识图（我） | 加一个函数：给一张图，返回“已经缩好的图（base64）”，有缓存就用缓存，没有就下载缩一下。认人、描述都不动 |
| `config.py` 的 `VISION_*` | 识图（我） | 加开关 `VISION_CHAT_SEES_IMAGE`（默认关，测完再开），以及最多带几张（默认 2，和现在一条消息最多看 2 张一致） |
| `textin.py` / `reply.py` | 聊天 agent | `rich_text(look=True)` 时顺便把这几张图记下来；`_build_prompt` 拼本轮最后那条消息时，把文字换成“文字 + 图片”的格式；重说（`_ask` 带 `more`）时同样带图；写进聊天记录的还是纯文字 |
| `prompts.py` 的聊天规则 | 聊天 agent | 补一句：“这一轮你能直接看到图；图里是谁以描述里的说法为准（‘伊蕾娜本人的画像’才是你），别自己认” |

空间评论（`qzone_diary._pic_hint`）、睡醒补回、引用的图，第一版先不带原图，只走聊天主流程。

## 测试点（动手前先定）

测的办法：拿一批“上下文 + 带图的一句话”，同样的提示各问几遍，比较“只给描述”和“描述加原图”。

| # | 场景 | 用的图 | 看什么 |
|---|---|---|---|
| 1 | 梗图接上下文（比如对方说“你怎么这么慢”，发一张翻白眼的表情） | 表情库、复杂图里的梗图 | 回复有没有接住图的意思 |
| 2 | 聊天截图（她自己说过的话也在里面） | `tools\识图截图\` | 能不能看出哪句是她说的；会不会把左右弄反 |
| 3 | 别的灰发角色的图，配一句“这是你吗” | `tools\识图对照图\` | **不能认成自己**。最要紧的一项，旧问题就是这个 |
| 4 | 她自己的图 | 表情库 | 还能认出自己 |
| 5 | 实物照片（手办） | `tools\识图实物照片\` | 知道是人偶 |
| 6 | 普通照片（食物、风景） | 测试用图 | 不乱发挥 |
| 7 | 全部场景 | — | 回复里有没有“动漫”“二次元”“角色”这类出戏词；回复长度；每轮多花多少 token |

判定：A 在 1、2 上明显更好，3、4、5 不比现在差，出戏词不增加，才打开开关。

测试工具要按聊天主流程拼提示（人设、记忆、聊天规则），这部分在聊天 agent 那边，最好由他写回放，我提供图和判定口径。
