# 问题排查记录：启动卡在"Current Env: prod"

> 日期：2026-09-28 17:20～17:33

## 现象

双击 `start.bat` 后只出现两行就不动了，按回车、Esc、Ctrl+C 都没反应：

```
09-28 17:20:17 [SUCCESS] nonebot | NoneBot is initializing...
09-28 17:20:17 [INFO] nonebot | Current Env: prod
```

`data\logs\bot_2026-09-28.log` 里没有这次启动的任何记录。同一套代码在当天 03:16 能正常启动，所以不是凌晨人设改动引起的。

## 排查

新增 `启动诊断.bat`（`tools\startup_diag.py`）：按 bot.py 的顺序一步步导入、加载插件，不连 QQ；卡住时用 faulthandler 把调用栈写进 `data\logs\启动诊断.txt`。

结果：导入 `onnxruntime`（本机识图用）时卡住，调用栈停在：

```
platform.py line 347 in _wmi_query
platform.py line 408 in _win32_ver
platform.py line 1090 in system
onnxruntime\capi\_pybind_state.py line 14
```

## 原因

onnxruntime 导入时会调用 `platform.system()`。Python 3.12 以后，在 Windows 上这个函数会通过 **WMI 服务**查询系统版本。当天电脑上的 WMI 服务没有响应，查询一直等不到结果，程序就卡在这里。这个等待发生在系统调用里，所以 Ctrl+C 也打断不了。

## 修复

`bot.py` 开头在导入任何库之前，把 `platform._wmi_query` 换成直接抛 `OSError`。Python 自带的回退逻辑会改用 `sys.getwindowsversion()` 和 `ver` 命令获取版本，结果一样。只在 Windows 上生效，服务器（Linux）不受影响。

修复后诊断 1.7 秒加载完成；17:33 start.bat 正常启动，人设 8757 字已加载。

## 以后再遇到启动卡住

1. 关掉所有命令行窗口；关不掉就在任务管理器里结束 `python.exe`。
2. 双击 `启动诊断.bat`，最多 1 分半会自己结束。
3. 看 `data\logs\启动诊断.txt` 最后停在哪一步；卡住时，下面的调用栈就是卡住的位置。
