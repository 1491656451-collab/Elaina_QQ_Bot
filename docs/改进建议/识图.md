## 2. 改了什么

### 识1：大图不再撑爆内存（`tagger.py`）

- 打开图片后先看尺寸（这时还没解码），超过约 1600 万像素（比如 4000×4000）就直接跳过，日志写“角色识别：图太大（8000×8000），跳过”。
- JPEG 按缩小的比例解码；其他格式先缩到 448 像素，再垫白底、铺正方形，格式转换全在小图上做。
- 预处理也放进了锁里，两张图同时来也只会一张一张处理。
- 太大没识别的图会在缓存里做记号，不会每次重新下载，也不会被当成“确定不是她”而加上“（画的不是你）”。

**实测**（同一台机器，新旧代码对比预处理的内存峰值）：

| 图 | 旧代码 | 新代码 |
|---|---|---|
| 8000×8000 PNG（文件只有 258 KB） | +769 MB | 跳过，+0 MB |
| 12000×9000 PNG（436 KB） | +1273 MB | 跳过，+0 MB |
| 3900×3900 PNG | +211 MB | +103 MB |
| 3900×3900 JPEG | +211 MB | +0 MB（按比例解码） |

新旧预处理的输出对比：用你那张便服伊蕾娜图和几种格式各测了一次，像素平均差在 0.1～2.3（满分 255）之间，识别结果不受影响。

### 识2：关掉内存池（`tagger.py`）

- `enable_cpu_mem_arena = False`：识别完把临时内存还给系统。
- 模型本身还是启动时加载、一直常驻。上服务器后先实测：空闲时和连续识别 5 张图后各看一次内存。不够用再做“用时加载、空闲 30 分钟释放”，代价是每次重新加载要多等约 2 秒。

### 识3：线程数（`config.py`、`.env.example`、部署指南）

- 代码默认值还是 2，本机不变。
- `.env.example` 加了 `VISION_TAGGER_THREADS=2` 和说明；部署指南 §5.11 加了一句“搬到 2 核的服务器上建议设成 1”。

### 识4：只在确认文件坏了才删模型（`tagger.py`）

满足下面任意一条，才判定文件坏了，删掉后下次启动重新下载：

- 报错是解析失败（`INVALID_PROTOBUF`）。
- 文件小于 100 MB（v3 系列模型都在 300 MB 以上）。
- 和自动下载时记下的大小对不上。现在下载完会多存一个 `model.onnx.size`；手动下载的没有这个文件，就不查这一条。

其他错误，比如内存不够（`bad allocation`），都保留文件，只在日志里提示“文件看起来是完整的，所以没删”。标签表和模型对不上时只删标签表（300 KB），不删模型。部署指南第 7 节加了这条提示对应的处理办法。

**实测**：

| 情况 | 结果 |
|---|---|
| 截断的小文件 | 删 ✅ |
| 150 MB 的坏文件（解析失败） | 删 ✅ |
| 完整大小 + 模拟内存不够 | **保留** ✅ |
| 大小和下载记录对不上 | 删 ✅ |
| 标签表对不上 | 只删标签表 ✅ |
| 正常模型 | 正常启用 ✅ |

### 识6：缓存截断保留手动纠正（`vision.py`）

- 每次用到一张图，就把它挪到“最近用过”。超过 2000 条时，丢最久没用过的。
- `/认图` 纠正过的条目一律保留，不算在截断里。

**实测**：先纠正 2 张图，再塞 2100 条假条目。结果留下 2000 条，2 张纠正都在；中途又被用到的“常用表情”留下了，只见过一次的旧图和最早的假条目被丢掉了。

### 识7：缓存原子写盘、坏文件留底（`vision.py`）

- 先写 `vision_cache.json.tmp`，写完再替换，写到一半崩溃也不会损坏原文件。
- 读取失败时，把坏文件改名为 `vision_cache.bad-时间.json` 留底，日志里打警告，不再悄悄清空。

**实测**：写入后没有 `.tmp` 残留；故意写一个半截的 JSON，启动时正确改名留底并提示。

## 3. 还没做的

1. **识5**：和《聊天.md》的主流程改动一起做。
2. **识8**：迁服务器时把 `onnxruntime`、`numpy`、`Pillow` 拆到 `requirements-vision.txt`，单独安装，装不上只提示。
3. **识2 的后半部分**：上服务器后按实测内存决定。
4. 顺带发现：说说图库 `gallery.py` 压缩原图时，也是按原尺寸解码（图库里最大一张 11.8 MB）。图库里都是你自己放的图，风险比群图低，但上 2G 服务器前最好也照识1 的办法改一下。这个文件这次没动。

---

## 4. 要你做的

- **重开 `start.bat`**，让改动生效。本机的 `.env` 不用改。
- 上服务器时，在服务器的 `.env` 里加 `VISION_TAGGER_THREADS=1`。

## 5. 上线后怎么验证

- **大图**：往测试群发一张 8000×8000 的图，日志里应该有“角色识别：图太大（8000×8000），跳过”，任务管理器里机器人的内存不应该暴涨。
- **内存**：机器人空闲时和连续识别 5 张图后，各看一次内存占用，记进部署指南。
- **线程**：服务器上设成 1 之后，识别一张图时 `top` 里不应该两个核都满。
- **缓存**：用 `/认图` 纠正过的图，过几周再发一次，结论应该还在。
