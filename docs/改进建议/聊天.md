## 5. 长期记忆（`memory.py`）

| 编号 | 严重度 | 问题 | 位置 | 建议 |
|---|---|---|---|---|
| 聊13 | 高 | **群的长期记忆一直整理失败，而且会一直卡住**（你看到的那条报错）。9/27 把每人档案从 12 条加到 20 条、群往事从 8 条加到 12 条，但整理的输出上限还是 2000 token；模型要把这批里每个人的整份档案重写一遍，4 个人就可能写不下，被截断作废。另外整理共用 60 秒超时，SDK 还会自动重试 2 次、每次都计费。失败后只在下一条消息进来时重试，批越攒越大越难成功；重启后也不会主动补做 | `memory.py` 53-54、206-236；`config.py` 80-82；`__init__.py` 68-71 | **马上能做**：`.env` 加 `MEMORY_SUMMARY_MAX_TOKENS=4000`。**根本改法**：输出改成“只给增减”（每人只列新增、修改、删除哪几条，没变化的人不输出），输出长度就不随档案变长；每次最多整理 16 条；整理请求单独用 180 秒超时、不自动重试；失败后按 5→15→60 分钟退避，另起定时任务每 10～20 分钟补做一次，启动时也扫一次；同一批连续失败 3 次就移到 `pending/dead/` 并私信管理员；日志记下 `finish_reason` 和实际用了多少 token |
| 聊14 | 高 | **写 JSON 不是原子的，出意外可能清空档案。** Windows 上 `write_text` 先清空文件再写，写到一半断电或被杀进程会留下空文件或半截文件；下次读失败返回空档案，马上又被存回去，这个人的印象、好感、计数全没了。如果半截断在中文字中间，还会抛一个没被捕获的错误，这个人之后每条消息都报错 | `memory.py` 27-36 | 先写 `.tmp` 再 `os.replace`（照抄 `stickers.py` 137-140）；读失败时把坏文件改名 `.corrupt-时间` 留底并打警告，不要直接返回默认值再覆盖 |
| 聊15 | 高 | **模型返回空内容时，群往事会被清空。** DeepSeek 的 JSON 模式偶尔返回空内容，代码当成 `{}`，把群往事存成空列表，这批待整理的消息也被删掉；模型给某人返回空 facts，这个人的档案也被清空 | `memory.py` 233、246-250、266-281 | 先校验返回结构，缺字段就按失败处理、保留待整理消息；某人 facts 突然少一半以上时保留旧值并记日志（改成聊13 的“只给增减”后自然解决） |
| 聊16 | 中 | 同一个人的群聊和私聊同时整理时，后完成的会用旧快照覆盖先完成的（好感分没问题，只丢 facts） | `memory.py` 197、204、247-250 | 聊13 改成“只给增减”后自然解决；或者加一把按 QQ 号的锁 |
| 聊17 | 中 | 待整理队列截到 40 条后按下标删除，卡住时可能误删还没整理的新消息 | `memory.py` 151、277 | 每条加一个递增 id，按 id 删 |
| 聊18 | 中 | 整理写到一半出错（比如杀毒软件占用文件），前几个人的好感已经落盘、待整理消息没删，重试时好感重复加减 | `memory.py` 238-281 | 先在内存里算好所有结果，再统一写入；每批记一个编号，同一批不重复加分 |

## 7. 配置和文档

- **注释和默认值互相矛盾**：
  - `.env.example` 说“正常聊天每次 +1 好感”，但 `AFFECTION_CHAT_GAIN` 默认是 0。
  - `config.py`、`.env.example`、`memory.py` 都说“被挤出短期记忆的消息攒够几条就整理”，实际是每一轮都直接加进待整理。
  - `.env.example` 里 `SMART_MIN_INTERVAL=15`，`config.py` 默认 60。
  - `.env.example` 写 `personas/elaina.md`，`config.py` 默认 `personas/default.md`（开源版用 default 更一致）。
- **`.env.example` 缺了常用项**：`LLM_TIMEOUT`（和聊13 直接相关）、`PEAK_RANGES`、`PEAK_MAX_TOKENS`、好感衰减、`AFFECTION_DAILY_CAP`、知识库检索条数等，建议补上并默认注释掉。
- **`当前参数一览.md` 漏了 `QZONE_STARTUP_GRACE_MINUTES`**（默认 30）。

## 8. 人设（`personas/elaina.md`）

- 约 7300 字，每次调用约 4100 token。它是固定前缀，DeepSeek 的缓存基本能命中，所以省钱效果有限，精简主要是为了让模型注意力更集中。
- **一处自相矛盾**：开头“你是……轻小说《魔女之旅》的主角”，和后面“不要说自己是小说角色”“《魔女之旅》是你的日记”冲突。建议开头改成“你是旅行魔女伊蕾娜”。
- **可以精简**：
  - “旅途回忆总览”（约 1000 token）和知识库检索的内容大量重叠，可以压到十行以内，只留关键人物关系。
  - 艾维莉亚的“天才魔法师”“极度恋姐”在同一段写了两遍；美奈“陪她找想做的事”在两处重复。
- 示例里“问蘑菇：‘我拒绝。’”意思含糊，可能本意是“请你吃蘑菇”。
- “看到自己的画像”“甩小画像”两节见《识图.md》《表情.md》。

## 改完怎么验证

- **下线**：机器人在线时在 NapCat 里退出登录（模拟下线），之后有人私聊她，不应该回；重新登录后前 N 分钟也不回，之后补回离线期间的私聊。
- **限额落盘**：连续回复几条后重开 `start.bat`，`data/rate_state.json` 里的计数还在。
- **长期记忆**：群里聊够一批后，看日志有没有“整理失败/被截断”，`groups/<群号>.json` 的更新时间有没有变；把 `pending` 里那 21 条消化掉。
- **原子写**：整理过程中强行关掉窗口，重开后档案文件还能正常读。
- **身材梗**：陌生人说一句相关的话，好感只扣一次（看 `/好感`）。
