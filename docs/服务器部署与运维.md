> 编写：2026-09-28 晚，按当天实际搬到服务器的过程整理
> 这份是**服务器专用**的说明：服务器上装了什么、放在哪、平时怎么管、怎么更新、出问题怎么办，以及从零重装的完整步骤。Windows 本机的部署见《QQ机器人方案与部署指南.md》第 4 节。

| 项 | 值 |

## 3. 两个服务

NapCat 和机器人都做成了系统服务，**开机自动启动**。

### napcat.service

`/etc/systemd/system/napcat.service`：

```ini
[Unit]
Description=NapCat (QQ)
After=network-online.target
Wants=network-online.target

[Service]
User=admin
WorkingDirectory=/home/admin
ExecStart=/usr/bin/xvfb-run -a /home/admin/Napcat/opt/QQ/qq --no-sandbox -q <小号QQ号>
Restart=on-failure
RestartSec=600
StandardOutput=append:/home/admin/napcat.log
StandardError=append:/home/admin/napcat.log

[Install]
WantedBy=multi-user.target
```

- `xvfb-run`：服务器没有屏幕，给 QQ 一个虚拟显示器。
- `-q <小号QQ号>`：用上次扫码留下的记录快速登录。被踢以后这个记录会失效，要重新扫码（第 4 节）。
- `RestartSec=600`：崩了**等 10 分钟再重启**，避免被踢后几秒就重登。

### qqbot.service

`/etc/systemd/system/qqbot.service`：

```ini
[Unit]
Description=QQ bot (Elaina)
After=network-online.target napcat.service

[Service]
User=admin
WorkingDirectory=/home/admin/QQBot/bot
ExecStart=/home/admin/QQBot/bot/.venv/bin/python bot.py
Restart=on-failure
RestartSec=30
MemoryMax=1100M
MemorySwapMax=1G

[Install]
WantedBy=multi-user.target
```

- `MemoryMax=1100M`：机器人最多用 1.1G 内存（再加最多 1G swap）。超了只会重启机器人，**不会再把整台服务器拖死**（9/28 原版识图模型就是这样把服务器卡死的）。

> **9/28 晚的状态**：机器人已经由 `qqbot.service` 管理；NapCat 还在 `screen` 里运行（当晚扫码登录的就是它），**下次服务器重启后才会换成 `napcat.service`**。在那之前不要运行 `systemctl start/restart napcat`，否则会开出两个 NapCat 抢着登录同一个号。

## 4. 日常操作

在电脑的 PowerShell 里 `ssh admin@<服务器IP>` 连上服务器后：

| 想做什么 | 命令 |
|---|---|
| 看两个服务的状态 | `systemctl status qqbot napcat` |
| 重启机器人 | `sudo systemctl restart qqbot` |
| 停掉机器人 | `sudo systemctl stop qqbot` |
| 重启 NapCat（会重新登录一次，少用） | `sudo systemctl restart napcat` |
| 实时看机器人日志 | `tail -f ~/QQBot/bot/data/logs/bot_$(date +%F).log`（Ctrl+C 只是退出查看） |
| 实时看 NapCat 日志 | `tail -f ~/napcat.log` |
| 查有没有被踢 | `grep -E "KickedOffLine\|下线通知" ~/napcat.log \| tail -3` |
| 看内存 | `free -h` |
| 看机器人有没有连上 NapCat | `grep connected ~/QQBot/bot/data/logs/bot_$(date +%F).log \| tail -1` |

### 被踢下线、要重新扫码时

1. 先查原因：`grep -E "KickedOffLine|被踢|Worker|失效" ~/napcat.log | tail -5`。被踢的话记进《风控记录.md》，**最好隔一段时间再登**。
2. NapCat 被踢后会自己重启、等扫码（日志里出现“请扫描下面的二维码”）。在**电脑的 PowerShell** 里运行，把二维码下载下来直接打开：

   ```powershell
   scp admin@<服务器IP>:Napcat/opt/QQ/resources/app/app_launcher/napcat/cache/qrcode.png $env:TEMP\qr.png; start $env:TEMP\qr.png
   ```

   二维码大约 2 分钟过期，过期就再运行一次。用小号的手机 QQ 扫。
3. 扫完确认：`tail -3 ~/napcat.log`，以及机器人日志里出现新的 `connected`。
4. 机器人被踢后重新上线，会先安静 5 分钟，之后补回这段时间的私聊；空间功能要等 30～60 分钟才动。

### 快速登录失败、扫码后 QQ 崩溃（9/28 23:37～23:56 实际遇到）

- **快速登录报“你的用户身份已失效”**：腾讯把上次的登录凭证作废了（被踢过以后常见），只能重新扫码。服务器每次重启都有可能遇到。
- **快速登录一直卡在“正在快速登录”没下文**：凭证坏了。先 `sudo systemctl stop napcat`，再用不带 `-q` 的方式启动（见下面），扫码登录。
- **每次扫码确认后约 7 秒 QQ 就崩溃**（日志里 `Worker进程退出，退出码: 139`，然后又出新二维码）：QQ 在服务器上的本地数据坏了。把它挪开，让 QQ 像第一次那样重新生成，再扫码就好了：

  ```bash
  sudo systemctl stop napcat; screen -S napcat -X quit; pkill -f Napcat/opt/QQ/qq; sleep 3
  mv ~/.config/QQ ~/.config/QQ.bak_$(date +%m%d_%H%M)
  screen -dmS napcat bash -c "cd ~ && xvfb-run -a ~/Napcat/opt/QQ/qq --no-sandbox 2>&1 | tee -a ~/napcat.log"
  ```

  然后按上面的方法下载二维码扫码。`~/.config/QQ` 只是 QQ 客户端自己的缓存和本地消息记录，和机器人的记忆（`~/QQBot/bot/data`）无关；挪开的备份确认没问题后可以删。
- 这样在 screen 里登录的 NapCat，**下次服务器重启时会自动换回 `napcat.service`**，用的就是这次扫码存下的新凭证。在那之前别运行 `systemctl start napcat`，否则会开出两个 NapCat。
- **二维码要现下现扫**：大约 2 分钟过期，过期后 NapCat 会自动换一张，旧图扫了没用。

### 用 screen 时要注意

9/28 当晚 NapCat 还在 `screen` 里跑。`screen -r napcat` 可以进去看画面，**退出要按 Ctrl+A 松开，再按 D**；按 Ctrl+C 会把程序关掉。记不住就直接关掉 PowerShell 窗口，程序照常在后台跑。换成系统服务以后就不用 screen 了。

## 5. 更新

### 代码（走 GitHub）

完整流程是：**电脑上推送到 GitHub → 服务器上运行 `~/update.sh`**。

#### 第一步：在电脑上推送

在 `D:\QQBot` 打开 PowerShell：

```powershell
cd D:\QQBot
git status
```

**推之前一定先看 `git status` 列出的文件**，下面这些**绝对不能出现**（出现了说明 `.gitignore` 漏了，先别推，问 Claude）：

| 不能推的 | 为什么 |
|---|---|
| `bot/.env`、`server.txt` | 密钥、token、服务器地址 |
| `bot/data/`、`server_logs/` | 聊天记录、别人的 QQ 号和档案 |
| `bot/personas/elaina.md`、`docs/人设打磨备份/`、`docs/人设回归测试/` | 人设（有版权） |
| `bot/knowledge/` 里的摘要和角色档案、`novel/`、`bot/qzone/images/` | 小说内容、插画（有版权） |
| `docs/风控记录.md`、`docs/当前参数一览.md`、`docs/项目文件整理.md`、大部分“问题排查记录”（公开的只有启动卡住、沙耶设定错误两份） | 含真实 QQ 号、群号、聊天内容 |
| `NapCat.Shell/`、`*.db`、`qqbot.tgz` | 账号配置、QQ 数据库、搬家用的压缩包 |

新增了文档或文件、拿不准能不能公开时，先问 Claude；要不公开就在 `.gitignore` 里加一行。

确认没问题后推送（引号里写这次改了什么）：

```powershell
git add .
git commit -m "这次改了什么，比如：修复表情重复发送"
git push
```

最后出现 `main -> main` 就是推上去了。偶尔会报 502 之类的网络错误，再运行一次 `git push` 就行。

#### 第二步：在服务器上更新

`ssh admin@<服务器IP>` 连上服务器后运行：

   ```bash
   ~/update.sh
   ```

   它会：拉最新代码 → 列出这次更新了哪些提交 → `requirements.txt` 变了就补装依赖（用阿里云 pip 镜像）→ 重启机器人 → 45 秒后显示有没有连上。NapCat 不动，不用重新登录。已经是最新的话只显示“已经是最新，不用更新”。

`~/update.sh` 的内容：

```bash
#!/bin/bash
# 从 GitHub 拉最新代码 → 依赖变了就补装 → 重启机器人（NapCat 不动）
set -e
cd ~/QQBot
old=$(git rev-parse HEAD)
git pull --ff-only
new=$(git rev-parse HEAD)
if [ "$old" = "$new" ]; then echo "已经是最新，不用更新"; exit 0; fi
echo "这次更新了："; git log --oneline "$old..$new"
if ! git diff --quiet "$old" "$new" -- bot/requirements.txt; then
  echo "依赖有变化，补装中……"
  bot/.venv/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple/ -r bot/requirements.txt
fi
sudo systemctl restart qqbot
echo "已重启机器人，等 45 秒看有没有连上……"
sleep 45
systemctl is-active qqbot
grep -E "connected|已启动|ERROR|Traceback" bot/data/logs/bot_$(date +%F).log | tail -3
```

`git pull` 只更新仓库里有的文件。`.env`、`data/`、人设、知识库、小说、图库都在 `.gitignore` 里，不会被动到。

### 不上 GitHub 的文件（在电脑的 PowerShell 里用 scp 传）

| 改了什么 | 怎么传 | 之后 |
|---|---|---|
| 人设 | `scp D:\QQBot\bot\personas\elaina.md admin@<服务器IP>:QQBot/bot/personas/` | QQ 里发 `/重载人设` |
| 知识库 | `scp -r D:\QQBot\bot\knowledge admin@<服务器IP>:QQBot/bot/` | `sudo systemctl restart qqbot` |
| 说说配图 | `scp "D:\图片文件夹\*.jpg" admin@<服务器IP>:QQBot/bot/qzone/images/` | QQ 里发 `/说说 图库`（马上处理新图；不发也会在下次发说说前处理） |

### 配置

服务器的 `.env` 直接在服务器上改（`nano ~/QQBot/bot/.env`，Ctrl+O 保存、Ctrl+X 退出），然后 `sudo systemctl restart qqbot`。**不要**把电脑上的 `.env` 传过去覆盖。

### 表情

表情不是传文件：用手机登录小号，把表情**添加到收藏**，然后 QQ 里发 `/表情 刷新`。

### 不能从电脑搬到服务器的

`bot/data/` 整个文件夹。从 9/28 起服务器上的记忆、好感、空间记录才是最新的，拿电脑上的覆盖过去，她这段时间记住的事都会倒回去，空间还可能把旧评论重新回一遍。

## 6. 服务器的 .env 和电脑上不一样的地方

| 参数 | 服务器上的值 | 为什么 |
|---|---|---|
| `VISION_TAGGER_THREADS` | `1` | 2 核的机器，识图时别把两个核都占满，免得 NapCat 卡 |
| `VISION_TAGGER_REPO` | `SmilingWolf/wd-swinv2-tagger-v3-int8` | 用压缩版识图模型（第 7 节） |
| `VISION_TAGGER_THRESHOLD` | `0.72` | 压缩版的把握比原版略低，门槛相应调低 |
| `SMART_NAMES` | `["伊蕾娜","灰之魔女","魔女小姐","Elaina","屑魔女"]` | 9/28 的智能回复修复（见《智能回复机制与误判分析.md》）；电脑上的 `.env` 也应该有这一行 |

## 7. 识图：服务器上必须用压缩版模型

- **原版模型（446MB）在服务器上会把整台机器卡死**：加载时内存不够，系统忙着在内存和硬盘之间倒数据，连 SSH 都连不上，只能强制重启（9/28 21:10 前后）。
- **压缩版（int8，167MB）**：在电脑上用 `bot\量化识图模型.bat` 生成（`tools\quantize_tagger.py`），放在 `data\models\wd-swinv2-tagger-v3-int8\`，再用 scp 传到服务器同样的位置。
  - 对比结果见 `docs\识图模型量化对比.txt`：36 张有效图里，把握平均低 0.03；门槛 0.75 时有 2 张临界的图结论和原版不一样，门槛调到 0.72 后和原版完全一致（都认出 28 张）。
  - 在服务器上，压缩版算出来的分数比电脑上还略低一点（不同 CPU 的正常差别）。分数在 0.35～0.72 之间的图，会再让 DeepSeek 看一眼确认，所以临界的图不会直接漏掉。
  - 速度：服务器上每张约 2 秒（只用 1 个核）。
- **内存实测**（单独测试，限 900MB）：加载后 337MB，认图时最高 515MB（包含 Python 本身）。

### 内存情况（9/28 实测）

| 状态 | 已用 | 可用 |
|---|---|---|
| 刚开机，什么都没跑 | 约 420Mi | 1.2Gi |
| NapCat 已登录 + 机器人（识图关） | 858Mi | 754Mi |
| NapCat + 机器人 + 压缩版识图 | 1.1～1.2Gi | 410～455Mi |

swap 基本没用上。以后加功能要留意内存，`free -h` 的 available 低于 200Mi 就要小心了。

## 8. 从服务器拿日志回电脑

双击电脑上的 **`D:\QQBot\拉取服务器日志.bat`**，会下载到 `D:\QQBot\server_logs\日期_时间\`：

- 机器人日志（`bot_日期.log`，排查“回忆命中”这类问题要靠它）
- 风控记录、空间日志
- NapCat 日志（最近 2 万行）
- 聊天记录，也就是短期记忆（`history\`）
- **全部长期记忆和空间记录**（`data\`）：
  - `data\memory\users\QQ号.json`：每个人的档案（印象、好感、性别、聊天次数）
  - `data\memory\groups\群号.json`：群往事
  - `data\memory\pending\`：还没整理进档案的消息
  - `data\qzone\daily\`：每天的今日见闻；`data\qzone\*.json`：发过的说说、看过的评论、空间状态
  - 表情标签（`stickers\index.json`）、识图缓存（含 `/认图` 手动纠正）、重名记录、在线状态
- 一份 `说明.txt`，写着每个文件是什么

只下载，不改服务器上的任何东西。**拉下来的记忆只用来排查，不要复制到电脑的 `bot\data` 或传回服务器**：服务器上的才是最新的，覆盖了会让她的记忆倒回去。`server_logs/` 和 `server.txt` 都在 `.gitignore` 里。排查问题时把这个文件夹交给负责代码的 agent。

## 9. 从零重装（完整步骤）

万一要换服务器或者重装系统，按这个顺序来。每一步括号里是 9/28 实际遇到的坑。

### 9.1 买服务器、连上

1. 阿里云轻量应用服务器，**系统镜像**选 Ubuntu 24.04（不要选 OpenClaw 这类应用镜像，会多占内存），地域选你常在的城市。
2. 电脑 PowerShell 里生成密钥：`ssh-keygen -t ed25519`（三次回车），`type $env:USERPROFILE\.ssh\id_ed25519.pub` 复制那一行。
3. 用控制台的“远程连接”进服务器，把公钥放进去：

   ```bash
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   echo '粘贴公钥那一行' >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

   之后电脑上 `ssh admin@<服务器IP>` 就能免密登录。（阿里云的镜像默认关了密码登录，不建议打开。）
4. `sudo passwd admin` 设一个密码，`sudo` 时要用。

### 9.2 基础环境

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo apt update && sudo apt upgrade -y
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf && sudo sysctl --system
sudo apt install -y python3-venv git
```

（不需要 Docker：国内拉不到 Docker Hub，阿里云的镜像加速器里也没有 NapCat 的镜像。）

### 9.3 装 NapCat（不用 Docker，**不要加 sudo**）

```bash
curl -fL -m 30 -o napcat.sh https://ghfast.top/https://raw.githubusercontent.com/NapNeko/NapCat-Installer/main/script/install.sh
ls -l napcat.sh      # 9/28 时是 49247 字节
bash napcat.sh --docker n --cli n --proxy 0 --force
ls ~/Napcat/opt/QQ/qq && echo 安装位置正确
```

- （官方文档里的 `nclatest.znin.net` 从阿里云服务器连不上，改用 ghfast.top 加速地址下载脚本。）
- （**别用 sudo 运行**：用 sudo 会装进 `/root/Napcat`，admin 用不了。脚本需要权限时会自己要密码。）
- 装的是 NapCat 4.18.28 + LinuxQQ 3.2.30，和 Windows 上的 NapCat 版本一致。

把网页后台改成只允许本机访问：

```bash
CFG=~/Napcat/opt/QQ/resources/app/app_launcher/napcat/config/webui.json
sed -i 's/"host": *"[^"]*"/"host": "127.0.0.1"/' $CFG && grep '"host"' $CFG
```

### 9.4 传机器人过去

在电脑的 PowerShell 里打包（跳过 Windows 的 Python 环境、识图模型、日志）：

## 10. 踩过的坑（9/28）

| 坑 | 结果 | 怎么避开 |
|---|---|---|
| Docker Hub 连不上，阿里云镜像加速器里也没有 NapCat | `docker pull` 超时 / not found | 不用 Docker，用官方脚本直接装 |
| `nclatest.znin.net` 连不上 | 下载脚本一直 0 字节 | 用 `ghfast.top` 加速地址下载 |
| 用 `sudo` 运行 NapCat 安装脚本 | 装进了 `/root/Napcat` | 不加 sudo，重装 |
| 原版识图模型 | 服务器卡死，SSH 连不上，正常重启卡在“停止中” | 用压缩版；机器人服务加 `MemoryMax` |
| `requirements.lock` 锁了 Python 3.14 专用的版本 | Ubuntu 24.04（3.12）装不上 | 服务器用 `requirements.txt` |
| 在 `screen -r bot` 里按了 Ctrl+C | 机器人被关掉 | 退出 screen 用 Ctrl+A 再按 D |
| 在 `bot` 目录里启动 NapCat | QQ 把 `guild1.db` 这几个数据库文件建在了 `bot` 目录 | 系统服务的工作目录是 `/home/admin`；换成系统服务后可以删掉 `bot/guild1.db*` |
| 电脑上的 WMI 服务没响应 | pip、onnxruntime 一启动就卡住（和《问题排查记录-启动卡住.md》同一个原因） | 用 `tools\nowmi.py` 包一层，或者重启电脑 |
