## 1. 先说现状（查代码确认过）

| 事 | 现在的做法 | 和方案的关系 |
|---|---|---|
| 冒泡、插话 | 发出去以后只进这个群的聊天记录（`proactive_group.py`，`history.append` + `save_history`），**不交给长期记忆** | 方案要求冒泡交给近况；插话不交 |
| 写信 | 只进私聊聊天记录，另外 `ltm.mark_letter(qq)` 记下写信的时间；**信的内容不进长期记忆** | 方案要求进近况 + 收信人档案的"她说过" |
| 冷场搭话 | 只进私聊聊天记录（`proactive_private.py`），不进长期记忆 | 方案要求进近况 |
| 正常聊天里她讲的经历 | 整理时按人记进 `told`（"对这个人讲过什么"），没有"她自己"的一份 | 方案要求整理时另外输出一项给近况 |
| 每轮提示里的长期记忆 | `reply.py` 调 `ltm.context_for(...)`，拼进每轮末尾那段提示（`extra`）的第一块 | 【你的近况】放在它后面一块 |
| 晚上休息 | `sleep.asleep()`、`sleep.night_key()` | 事件调度直接用，不另设时间 |
| 测试模式 | `commands.in_test_mode(qq)`；开着时这个人的对话不进 `add_pending` | 见第 5 节 |

所以现在冒泡、写信、搭话里她编的旅途小事，**没有一条进过长期记忆**，聊天记录挤掉就忘了。这正是方案第 1 节第 1 条说的问题。

## 3. 数据（建议）

文件：`data/memory/self.json`。写文件沿用 `memory.py` 现在的 `_write`（先写临时文件再替换，读坏了改名留底）。

```json
{
  "place": {
    "name": "某小镇",
    "kind": "城镇",
    "novel": false,
    "since": "2026-10-23",
    "days": 3,
    "next": "往东的山路"
  },
  "trail": [
    {"name": "某片森林", "kind": "野外", "novel": false, "from": "2026-10-20", "to": "2026-10-22"}
  ],
  "items": [
    {
      "id": "e1729",
      "text": "在集市上被一只会学人说话的猫跟了半条街",
      "where": "某小镇", "where_kind": "城镇",
      "date": "2026-10-23", "time": "下午", "at": 1792731600,
      "source": "事件", "type": "怪人怪事",
      "mood": "好笑", "weight": 2,
      "told_in": ["group_555"]
    }
  ]
}
```

- `place`：现在在哪。`kind` 只有三种：城镇、野外、小说地点（小说地点时 `name` 用 `places.md` 里的名字，`novel` 为 true）。`days` 是这一段**打算**待几天，`next` 是下一站大概往哪走（可以空）。
- `trail`：最近走过的几段，用来避免地名近期重复、算"连着在野外几天"。保留多少段记忆 agent 定，建议 10 段左右。
- `items[].at`：这件事"发生"的时间（Unix 秒）。**下午的事件上午就生成好写进来，但到 `at` 之前取用函数不返回**。来自冒泡、聊天的条目 `at` 就是写入的时间。
- `items[].type`：只有 `source` 是"事件"的才有，记事件类型清单里的类型名，用来避免最近几天重复抽同一类。
- `items[].told_in`：讲过的会话（`group_xxx` / `private_xxx`），只给程序用，不给她看。
- `id`：随便什么不重复的短字符串，`/近况 删 N` 用序号，`id` 给程序之间传。

## 4. 函数接口（建议）

下面写成 `self_mem.xxx`，实际挂在哪个对象上由记忆 agent 定。

### 4.1 写入（聊天调用）

| 函数 | 什么时候调 | 说明 |
|---|---|---|
| `add_event(text, *, type, mood, at, where=None) -> dict \| None` | 随机事件生成好以后 | `where` 不给就用现在的 `place`。返回写进去的那条（带 `id`）；被去重、限量挡掉返回 None |
| `add_said(text, *, source, key, qq=None) -> None` | 冒泡、写信、冷场搭话**发出去以后** | `source`：冒泡 / 写信 / 搭话；`key`：在哪说的；`qq`：写信、搭话时对方是谁。插话不调 |
| `set_place(name, *, kind, days, next=None, novel=False) -> None` | 旅程换下一段时 | 旧的 `place` 挪进 `trail` |
| `get_place() -> dict` | 生成事件、拼提示时 | 返回 `place`，没有时返回空字典（第一次上线由聊天这边初始化一段） |
| `recent_types(days=3) -> list[str]` | 抽事件类型前 | 最近几天出过的事件类型 |
| `recent_places(n=10) -> list[dict]` | 选下一段去哪时 | `trail` 最近几段 + 现在这段 |

**`add_said` 收进来以后怎么处理，归记忆 agent**，聊天这边只要求三件事：

1. **当天就能查到**（方案第 6 节第 2 条）：比如先原样存一条、标记"还没整理"，取用时就能用；整理（判断是不是"自己的经历"、压短、和已有条目合并）可以晚一点做。
2. **同一件事合并**：她冒泡讲的就是今天的某个事件时，不要另记一条，而是在那条事件的 `told_in` 里加上这个 `key`。这样"这个群听过没有"才算得准。聊天这边**不知道她讲的是哪一条**，只能把原话交过来，合并只能在记忆这边做。
3. **写信**：除了近况，还要在收信人档案的"她说过"（`told`）里记一条"写信跟他讲过 ……"（方案 3.2）。建议 `add_said` 里 `source == "写信"` 时顺手做掉，聊天这边不另外调。

冒泡、搭话的原话里很多不是"经历"（随口问一句、吐槽天气），收不收由记忆 agent 判断；方案 5.2 第 3 条说"分不清的宁可不记"。

### 4.2 取用（聊天调用）

| 函数 | 什么时候调 | 返回 |
|---|---|---|
| `life_for_chat(key, text, recent, now=None) -> dict` | 每轮回消息拼提示时 | `{"place": "...", "today": [...], "related": [...]}`。`place` 是现在在哪、待了几天的一句话；`today` 是今天**已经发生**的事件；`related` 是按这句话和最近几句挑的一两条（不和 `today` 重复）。总共控制在 100 字左右。都没有就返回空字典 |
| `life_for_proactive(key, n=3, now=None) -> dict` | 冒泡、写信、搭话拼提示时 | `{"place": "...", "fresh": [...], "told_here": [...]}`。`fresh` 是最近几条**这个会话还没听过**的，今天发生的排前面；`told_here` 是这个会话已经听过的（让她别再讲），只给最近两三条 |

- 只返回 `at <= now` 的条目。
- 面包、钱、蘑菇这类条目沿用 `context_for` 现在的限量（对方没提最多带 1 条），由记忆 agent 在取用时做。
- 每条返回的是给她看的短句（已经去掉 `id`、`told_in` 这些），可以带"今天下午""前天"这类时间说法；时间怎么说建议用 `memory.py` 现成的 `_ago`。

### 4.3 拼进提示（聊天自己做，告诉记忆 agent 一声）

- `reply.py` 里放在 `long_memo` 后面一块（每轮末尾那段，本来就不走缓存，不影响花费）。
- 冒泡、写信、搭话的提示里，替换掉现在"随手编一件"的写法，改成"有近况先用近况，没有合适的才自己编一件"。
- 提示文字只写态度，不给例句（方案第 7 节第 5 条）。

### B. `add_said` 收进来以后怎么处理（第 4.1 节那三条）

**改**：不先原样存一条，而是**马上在后台调一次 flash** 把原话整理掉，一般几秒内就写进去，满足“当天就能查到”：

1. 喂给模型：这段原话 + 现在在哪 + 最近几条近况（带编号）。
2. 模型回答三样：
   - `same`：讲的是已有的哪一条（编号），没有就空。有就只在那条的 `told_in` 里加上这个 `key`，不另记。
   - `new`：原话里她讲成“自己最近经历”的事，压成一两句，带心情；随口问一句、吐槽天气、玩笑、比喻、小说往事都不算，**分不清的不记**。
   - `place_ok`：新的事和现在在哪对不对得上（人在森林却说“刚在镇上吃了……”就对不上）。对不上的不收，日志记一行。
3. 整理还没回来（几秒）或者出错、没钱的时候，原话先挂在 `told_here` 里返回（“你在这里刚说过：……”），免得她马上在同一个群又讲一遍；出错的跟着 `_memory_retry_loop` 重试。
4. 记账分类 **`memory_self`**（请一起告诉限额 agent）。一天十几次，每次几百 token，可以忽略。

写信：`source == "写信"` 时我顺手在收信人的 `told` 里记一条“写信跟他讲过：……”（第 4.1 节第 3 条，同意）。

### C. 聊天里她讲的经历（`self_events`）

- 整理时给模型看最近 8 条近况（带编号），让它多输出一项：`self_events: [{"text", "same", "mood"}]`。`same` 填编号时只记 `told_in`，不另记；只收她讲成“自己最近经历”的事，规则和 B 一样。
- **核对也管这一项**：现在的核对问“这是谁的事”，`self_events` 该答“伊蕾娜”；另外多一个选项“以前的事（小说里的往事）/ 玩笑”，答这个的不收。这样群里她讲故事多，也不容易收错。
- 测试模式：同意第 5 节，管理员的对话本来就不进整理，我只加一条程序测试确认。

### D. 取用

- **改**：`today`、`related`、`fresh`、`told_here` 每条返回 `{"text": ..., "when": "今天下午", "mood": "好笑"}`，不是拼好的一句话。“当时觉得好笑”这类要不要带、怎么带，由你在 `prompts.py` 里写（“轻”的做法：只在讲到这件事时带出来）。`place` 返回 `{"name", "kind", "days_here", "next"}`，“待了几天”我算好。
- 只返回 `at <= now` 的；“今天”按北京时间的日期算（她 23:30～07:30 睡觉，跨零点那段本来就没有事件）。
- 面包、钱、蘑菇：对方这句和最近几句没提时，`today` 和 `related` 合起来最多 1 条；`fresh` 里最多 1 条。
- 总长：`life_for_chat` 返回的文字合计不超过 100 字左右，超了先丢 `related`。

### E. 限量和遗忘

- 最多 30 条，超过两周的忘掉；超了先忘 `weight` 低、讲过的地方少的。
- 面包、钱、蘑菇这类条目，存的时候两周内最多 3 条（第 4 条起不收），从源头防滚雪球。
