# 方案：她自己定几点睡、几点起（11/13，聊天 agent，给用户审）

> 用户 11/13 想试试“休息时间、起床时间让模型自己定”。这份是方案和测试点，用户看过再动手。

## 1. 现在的样子

- `sleep.py`：`SLEEP_HOURS=23:30-07:30`，每晚前后各随机浮动 `SLEEP_JITTER_MINUTES=20` 分钟（按日期抽签，同一晚重启不变）。
- 用到“睡没睡”的地方（都走 `sleep_window()` / `sleep.asleep()`，不用改）：
  - 不回消息、不插话冒泡写信搭话（`addressed.py`、`quota.py`、`reply.py`）；
  - 睡前 20 分钟提示她慢慢流露困意、往收尾靠（`quota.py` 的 winddown）；
  - 到点给正在聊的人道晚安（`goodnight.py`）；
  - 睡着时来的话记下，醒来过 5～30 分钟补看（`wake.py`）；
  - 长期记忆按“睡着了”判断要不要整理（`memory_chat.py`）。

## 2. 做法

### 2.1 每天傍晚问她一次（`SLEEP_BY_MODEL`，默认先关）

- 时间：`SLEEP_PLAN_AT`（建议 20:00；机器人在这之后才启动、今晚还没定的，启动时补问一次）。
- 给她看：
  - 现在在哪、待了几天（近况里的 `place`）；
  - 今天说过的事（近况里今天的几件）；
  - 前两晚定的时间和理由（让作息有连续性，别今天 22 点明天 2 点）；
  - 今天星期几。
- 让她只回 JSON：`{"sleep": "23:10", "wake": "07:40", "why": "在野外露宿，天黑得早，早点睡"}`。提示里写清楚：按你今天在哪、做了什么、累不累来定，平常大概 23 点多睡、7 点多起，可以早可以晚，但别熬通宵。**不给例子时间**（给了她会照抄）。
- 一天 1 次调用（用聊天的 flash，几十个 token 输出），记在 `budget` 的新分类“定作息”里（限额 agent 的文件，要请他加一行分类名，或者先记在已有的“后台”里）。

### 2.2 程序兜底

| 参数 | 建议值 | 说明 |
|---|---|---|
| `SLEEP_START_RANGE` | 22:00-01:30 | 几点睡只能在这段里，超出就收到边上 |
| `SLEEP_END_RANGE` | 06:00-09:30 | 几点起只能在这段里 |
| `SLEEP_MIN_HOURS` / `SLEEP_MAX_HOURS` | 6 / 10 | 睡多久的上下限，超出就挪起床时间 |

- 没问到（出错、超时、JSON 读不出来、`SLEEP_BY_MODEL` 关着）：照现在的 `SLEEP_HOURS` + 随机浮动。
- 定好的存 `data/sleep_plan.json`（按“哪天晚上”记，留最近 14 晚），`sleep_window(night)` 先看这里，没有再走老算法。当晚不再改，重启也不变。

### 2.3 聊天里她说“我要睡了”（第二步再做，先不做）

- 她在离定好的入睡时间不到 30 分钟时说了晚安、要睡了：把入睡时间提前到说完后几分钟（像真人说完就去睡）。
- 更早说的不算（她常拿“我要睡了”结束不想聊的话题；别人一句“你该睡了”也不能让她 8 点下线）。
- 先上 2.1、2.2，看一周日志再定要不要做这一步。

### 2.4 管理员看 / 改

- `/作息`：今晚定的几点睡、几点起、理由、是不是兜底收过；最近 7 晚的列表。
- `/作息 重定`：马上再问她一次（测试用）。

### 2.5 理由要不要进近况

她说“今晚住旅馆，写日记写晚一点”，聊天时被问起要对得上。但近况是记忆 agent 的，先不碰：理由只进日志和 `/作息`；要进近况的话写交接给记忆 agent。

## 3. 测试点

### 3.1 程序测试（不调模型）

1. 关着 `SLEEP_BY_MODEL`：作息和现在一模一样（同一晚同样的时间）。
2. 开着、模型回了合法时间：`sleep_window()` 用她定的。
3. 超出范围的收回边上：凌晨 3 点睡 → 01:30；11 点起 → 09:30；睡 4 小时 → 挪到睡够 6 小时；睡 12 小时 → 挪到 10 小时。
4. 跨午夜：22:50 睡、07:10 起；00:40 睡、08:30 起，都算同一晚。
5. 模型出错、回的不是 JSON、时间写成“十一点”：用老算法，日志记一行。
6. 当晚只问一次；重启后读文件，不重问；20:00 以后才启动的补问一次；已经过了入睡时间才启动的不问（用老算法）。
7. 别的功能跟着走：睡前提示、道晚安、睡着不回、醒来补看都按她定的时间（各挑一个测）。
8. 文件只留最近 14 晚。

### 3.2 回放（调模型）

构造几种当天的情况，每种跑 10 次，看定出来的时间和理由：

| 题 | 当天的情况 | 看什么 |
|---|---|---|
| S1 | 在野外露宿第 3 天，今天说过在礁石上看浪 | 是不是偏早睡早起，理由说得通 |
| S2 | 刚到一个镇子住进旅馆，今天说过找了家咖啡厅 | 是不是偏晚睡、晚起 |
| S3 | 今天赶了一整天路（近况里说过“走了一整天”） | 是不是早睡 |
| S4 | 什么都没说过 | 是不是在 23 点前后、7 点前后，别乱定 |
| S5 | 前两晚都是 1 点睡（连着熬夜） | 今晚会不会往回拉，还是继续熬 |

数一下：时间分布（几点睡、几点起、睡几个小时）、被兜底收回的次数、理由和当天情况对不对得上、10 次里时间是不是全一样（太死）或者乱跳。

### 3.3 上线后看

- 一周里每晚定了几点、理由是什么（`/作息` 的列表）。
- 道晚安、补看有没有跟着走；有没有人在她“睡着”以后还收到回复。

## 4. 要改的文件

- 聊天 agent 的：`sleep.py`（读计划）、新文件 `sleep_plan.py`（傍晚问她、存文件、`/作息`）、`prompts.py`（问作息的提示）、`config.py`、`.env.example`、`tests\test_chat.py`；新回放工具 `tools\sleep_plan_compare.py`。
- 别人的：`budget.py` 加一个分类名“定作息”（限额 agent，可选）；近况（记忆 agent，第 2.5 节，先不做）。
- 不动人设。
