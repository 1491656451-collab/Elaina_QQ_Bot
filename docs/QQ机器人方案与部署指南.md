# QQ 角色扮演机器人（伊蕾娜）：方案与部署指南

> 适用场景：自用或小群使用，先在本机 Windows 跑通，之后再迁到服务器。
> 版本：v5 + QQ 空间日记 + 风控保护（2026-09-26 约 19:59）。v4 识图认出伊蕾娜（5.11），v5 发表情包（5.13），之后上线了 QQ 空间日记（5.14）和空间风控保护（5.15）。每一批更新的时间和内容见《版本说明与管理员指令.md》。
> 文中的限速数值按**你现在 `.env` 里的设置**写，和代码默认值不同的地方用括号注明默认值。

---

## 1. 方案选型

| 层 | 选择 | 理由 |
|---|---|---|
| 协议端（负责登录 QQ） | **NapCat**（NapCat.Shell 手动版） | 驱动的是官方 QQNT 客户端，行为和真实 QQ 最接近，目前最稳、维护也最活跃。go-cqhttp 已经停更，不要再用 |
| 机器人框架 | **NoneBot2**（Python） | 角色扮演需要精细控制提示词、记忆和知识检索，写代码最灵活 |
| 大模型 | **DeepSeek `deepseek-flash`** | 国内直连、便宜，中文角色扮演效果好。旧模型名 `deepseek-chat` 已在 2026-07-24 停用 |

### 关于"最不容易被封"

封号风险主要取决于两点：协议端是什么，以及机器人怎么说话。选 NoneBot2 还是 Koishi 对此没有影响。本方案在这两方面都选了风险最低的做法：

- **协议端**：NapCat 驱动的是真实的 QQ 客户端。
- **说话方式**：插件自带拟人节奏：只在被 @ 或被回复时开口，回复前随机"打字"延迟，同一个人有冷却时间，全局每分钟限速，还可以设群白名单。

即便如此，非官方方案都**无法保证不被封**，下面几条请务必做到：

1. **用小号**，最好是注册有一段时间、实名并绑定了手机的号。
2. 先只在 1～2 个自己的小群里运行，并且设置 `GROUP_WHITELIST`。
3. 不要让机器人主动加群、加好友、群发消息或发链接。
4. 登录的设备和 IP 尽量固定。
5. 如果收到"账号异常"或验证提示，先停一两天再上线。
6. **QQ 空间的写操作（发说说、评论、回复）风险比聊天高**：程序是拿 NapCat 的凭证直接调网页接口，不是真人在手机上点。9/26 那次设备被下线，导火索就是空间写操作（见《风控记录.md》#2），所以空间功能做了降频和自动熔断（5.15）。

## 4. 部署步骤（Windows 本机）

### 4.1 准备

1. 安装 **Python 3.10 或更高版本**，安装时勾选 **Add Python to PATH**。
2. 在 DeepSeek 开放平台（https://platform.deepseek.com/ ）充值少量余额，创建一个 API Key。
3. 准备一个 QQ 小号。

### 4.2 安装 NapCat（手动版）

> 不要用 `NapCat.Shell.Windows.OneKey.zip` 一键包：它内置的 QQ 下载地址已经失效，会报"HTTP 404，下载QQ失败"。

1. 从 QQ 官网 https://im.qq.com/pcqq 下载并安装最新版 Windows QQ。
2. 从 https://github.com/NapNeko/NapCatQQ/releases 下载 **`NapCat.Shell.zip`**，解压到 `D:\QQBot\NapCat.Shell`。
3. 双击 `launcher.bat`（Windows 10 用 `launcher-win10.bat`），控制台会出现二维码，用**小号**扫码登录。
4. **以后免扫码登录**：打开 `NapCat.Shell\config\webui.json`，把 `"autoLoginAccount": ""` 改成 `"autoLoginAccount": "小号QQ号"`，保存后重启 NapCat。之后每次启动都会自动用这个号快速登录，日志里能看到 `正在快速登录 小号QQ号`。
   - **只写 `-q` 参数不管用**：`启动.bat` 里写的 `launcher.bat -q 小号QQ号`，参数只传到了启动器，启动器再去启动 QQ 时没把它带过去（日志里 `Boot Command` 那行只有 `QQ.exe --enable-logging`），NapCat 会报“没有 -q 指令指定快速登录”。以现在的版本（NapCat 4.18.28 + QQ 9.9.35）为准；`启动.bat` 留着当启动快捷方式用就行。
   - **一定要指定账号**：NapCat 用的是电脑上装的 QQ，快速登录列表读的是这个 QQ 在本机存的登录记录。你在这台电脑上登过的其他号（比如大号）也会出现在列表里。不指定的话，NapCat 会自己从列表里挑一个，万一挑中大号，机器人就会用大号的身份说话。
   - **快速登录的前提**：这个号至少用二维码成功登录过一次，本机才有记录。

### 4.3 打开 WebUI

- NapCat 启动日志里有一行 `WebUi User Panel Url: http://127.0.0.1:6099/webui?token=xxxx`，把这个地址复制到浏览器打开。
- 如果需要输入 token：它在日志里 `WebUi Token:` 那一行，也可以在 `NapCat.Shell\config\webui.json` 里找到。
- 注意：这个 WebUI 登录 token，和下面连接 NoneBot 用的 token 是两回事。

### 4.4 在 WebUI 里新建连接

进入 **网络配置 → 新建**，类型选 **Websocket Client（客户端）**，不要选 Server：

| 项 | 值 |
|---|---|
| 启用 | 打开 |
| 名称 | `nonebot`（必填） |
| URL | `ws://127.0.0.1:8081/onebot/v11/ws` |
| 消息格式 | Array |
| Token | 和 `.env` 里 `ONEBOT_ACCESS_TOKEN` **一字不差** |
| 心跳 / 重连间隔 | 默认 30000 |

> 为什么用 8081 端口：8080 常被 Steam（steamwebhelper.exe）占用，占用时 NoneBot 会报 `[Errno 10048]`。

### 4.5 配置并启动机器人

1. 双击 `bot\start.bat`。第一次运行会自动建虚拟环境、安装依赖，然后打开 `.env`。
2. `.env` 里的关键项：

```
PORT=8081
ONEBOT_ACCESS_TOKEN=与NapCat一致
SUPERUSERS=["你的大号QQ"]
NICKNAME=["伊蕾娜小姐", "伊蕾娜"]     ← 中括号里每个名字都要用英文双引号
DEEPSEEK_API_KEY=sk-...
DEEPSEEK_MODEL=deepseek-flash
PERSONA_FILE=personas/elaina.md
GROUP_WHITELIST=[群号]               ← 群号是数字，不加引号
QZONE_ENABLED=true                   ← QQ 空间日记（代码默认关，见 5.14）
```

全部参数的说明见《版本说明与管理员指令.md》第 4 节。

3. 再次双击 start.bat。依次出现下面几条日志，就说明一切正常：
   - `知识库：索引建立完成…`（第一次大约 5～20 秒，之后直接读缓存）
   - `角色扮演聊天已启动`
   - `Uvicorn running on http://127.0.0.1:8081`
   - 最多等 30 秒后出现 `Bot xxxx connected`

### 4.6 哪些窗口要一直开着

| 窗口 | 关掉的后果 |
|---|---|
| NapCat 窗口（launcher.bat 打开的） | 小号下线 |
| 机器人窗口（start.bat 打开的） | 机器人在线，但不会回复 |

浏览器里的 WebUI 可以关。电脑睡眠时机器人也会下线。

| 改了什么 | 要重开什么 |
|---|---|
| `.env` | 只重开 start.bat |
| 人设文件 | 都不用重开，在群里 @ 它发 `/重载人设` |
| 插件代码（`plugins\` 里的 .py） | 只重开 start.bat |

- **尽量只重开 start.bat，别动 NapCat**：重开 NapCat 就是重新登录一次小号，被下线后也建议等半天到一天再扫码（见《风控记录.md》）。
| NapCat WebUI 配置 | 一般保存后就自动生效 |

## 5. 功能说明

### 5.1 她什么时候会回复（群聊）

| 情况 | 回不回 | 说明 |
|---|---|---|
| @ 她、回复她的消息、以昵称开头叫她 | ✅ 一定回 | |
| 刚叫过她的人，30 秒内接着说的话 | ✅ 直接回 | 例如先发"@伊蕾娜"，再发"陪我聊聊"。时间窗口由 `FOLLOWUP_WINDOW` 控制 |
| 同一个人连着发好几条 | ✅ 合成一次回 | 先等一等，把分开发的几条当成一句话来回；看起来没说完就多等（最多 8 秒），说完了就少等（3 秒），见 5.2d |
| 消息里提到她（伊蕾娜、灰之魔女、昵称等），但没 @ | 🤔 先判断 | 让模型判断一下是不是在跟她说话：是就回；群友只是在聊动画角色就不回 |
| 她刚在群里说完话（90 秒内），有人接话、带"你"或问号 | 🤔 先判断 | 同上 |
| 没 @ 她，只发了一张**她的图** | 🎲 可能回 | 本机认出图里是伊蕾娜时，60% 概率看一眼、说一句；同一个群至少隔 10 分钟，同一张图一天只搭一次（见 5.11） |
| 其他普通群聊 | ❌ 不回 | 不花 token，只进"旁听"暂存 |

- **防刷屏**："没 @ 也回复"的情况，同一个群至少间隔 120 秒（`SMART_MIN_INTERVAL=120`，代码默认 60）。另外还受个人冷却（5 秒）和全局限速（每分钟 8 条）约束。
- **关闭**：不想要这些，设 `SMART_REPLY=false`，就只在被 @、被叫到的时候回。
- **怎么发**：她要发言时，如果群里在那条消息之后没人说话，就直接发；如果中间有人插话，就用"回复"引用原消息。
- **私聊**：好友私聊每条都回（`ENABLE_PRIVATE=false` 关闭）。默认不回群里发起的临时会话（`PRIVATE_FRIENDS_ONLY`），因为临时会话更容易触发风控。
- **只用私聊**：设 `ENABLE_GROUP=false`，群里她就完全不说话，也不旁听、不做判断。
- **能力边界**：能看图（见 5.11）；听不了语音、看不了视频；会发文字，偶尔发表情包（见 5.13）。

### 5.2 回复长度

- **日常闲聊**：要求回复**约 10～30 个汉字**（一两句）；上限 80 token（`SHORT_REPLY_MAX_TOKENS`）。语气冷还是热由“熟悉程度”决定（见 5.9）。
- **可以说长一点的情况**：对方请她讲故事、问具体经历、要她详细解释、认真倾诉烦恼（例如"难过""怎么办"），或者对方自己写了一大段。这时上限 200 token，约 150 字。
- **每轮提示**：每轮都会在最后提示她"这次该短还是可以长"。人设里的示例台词也都改短了。
- **超长截断**：回复超过上限时，会切到最后一个完整的句子，不会发出半句话。

### 5.2b 像真人一样说话

- **长短随机**：日常闲聊每轮随机提示长度。约 30% 只回几个字（“嗯。”“蛤？”），约 45% 回一句话，约 25% 连发两三句短句。这样每次回复长度不会都差不多。
- **分条发送**：一次回复会拆成几条 QQ 消息依次发出，最多 3 条（`MAX_BUBBLES`）。拆分规则：
  - 模型自己换了行，就按换行拆。
  - 没换行但有几句话，有 60% 的概率按句子拆。
  - 每条之间先停顿 1.5～3.5 秒，再按下一条的字数算打字时间（约每秒 4 个字，每次快慢略有不同）。比如一条 10 个字的消息，前面大约隔 4～7 秒。
  - 大部分消息末尾不带句号。
- **只引用一次**：群聊里如果需要引用原消息，只在第一条引用。
- **计入限额**：多发的那几条也计入每小时限额，不会因为拆条而多发、增加风控风险。
- **关闭**：`MULTI_MESSAGE=false` 就恢复成一次只发一条。

### 5.2c 一次只回一个人、排队、补回未读

- **一次只回一个人**：她同一时间只给一个人打字。几个人同时找她时，她按顺序一个一个回：回完一个人，停 2～5 秒（像切换聊天窗口），再开始给下一个人打字。模型可以同时在后台想，只有打字和发送是排队的。
- **排队而不是丢掉**：
  - 同一个人连着发：等一等合成一条回（见 5.2d）；她正在回的时候又发了，回完这条再回下一条。
  - 个人冷却、每分钟限额满了：排队等一等再回，最多等 90 秒（`QUEUE_MAX_WAIT`）。
  - 每小时限额满了：还是不回（她已经说过“我要上路了”）。
  - 群聊里她排队期间有别人插话，她的第一条会引用原消息。
- **补回未读（仅私聊）**：
  - 机器人在线时每分钟记一次时间。电脑关机、NapCat 掉线或重启后重新连上时，会查一下这段时间里谁给她发过私聊、她还没回。
  - 找到的人按先后顺序补回，每人之间隔 20～90 秒，一次最多 5 个人。同一个人的几条未读合成一条回。
  - 她会自然地带一句“刚才在赶路，没看到”，不会提掉线、离线。
  - 不补：超过 12 小时的未读、非好友、指令、在线时已经处理过的消息。
  - 群聊的未读不补：群里的话题早就过去了，突然回复很奇怪，也容易触发风控。
  - 第一次启动时不知道什么时候离线的，所以不会去翻旧消息。
  - 用的是 NapCat 的 `get_recent_contact` 和 `get_friend_msg_history` 接口。前者拿不到时，改为检查所有聊过天的好友。
  - 关闭：`CATCHUP_ENABLED=false`。

### 5.2d 分条发送、水话

- **等对方把话说完**：收到消息先不急着回，等一等，同一个人接着发的合成一条再回。每来一条新的，就重新计时。等多久看最后一条像不像说完了：

| 最后一条 | 例子 | 等多久 |
|---|---|---|
| 看起来还没说完 | “我跟你说”“然后”“那个”“我觉得”、逗号结尾、只叫了她一声（“伊蕾娜”“在吗”“@她”） | 8 秒（`MERGE_WAIT_INCOMPLETE`） |
| 看起来说完了 | 问号、感叹号、句号结尾；“吗”“呢”“吧”“啊”结尾；12 个字以上的整句 | 3 秒（`MERGE_WAIT_COMPLETE`） |
| 看不出来 | “面包”“好” | 4 秒（`MERGE_WAIT`） |

  - 从第一条算起最多等 20 秒（`MERGE_WAIT_MAX`），到点就回，免得对方一直发、她一直不回。
  - 这是按文字判断的，不调用模型，不花 token。
- **水话不一定接**：
  - 对方只说“哈哈”“嗯嗯”“好的”“ok”“确实”、只发一个表情：按关系远近，有一定概率直接不回（讨厌 90%、陌生人 70%、熟人 50%、很熟 30%，`SKIP_FILLER_PROB`）。这种情况不调用模型，不花 token。
  - 其他短消息（12 字以内、不是问句），比如“那我先去吃饭了”：告诉她可以不回，她觉得没必要接话就不回（`SKIP_BY_MODEL`）。
  - 她上一句在问对方时，对方“嗯”一声算回答，照样接着聊。
  - 不回的话照样记进聊天记录，下次聊天她知道对方说过什么。
  - 关闭：`SKIP_FILLER=false`、`SKIP_BY_MODEL=false`。

### 5.3 记忆

| 记忆 | 内容 | 存放位置 |
|---|---|---|
| 短期记忆 | 群聊记最近 10 条，私聊记最近 20 条 | `data\history` |
| 长期记忆·个人档案 | 每个人一份，群聊和私聊共用：称呼偏好、喜好、身份、近期计划、和她的约定或梗（最多 12 条），以及好感分 | `data\memory\users\QQ号.json` |
| 长期记忆·群往事 | 这个群一起聊过、玩过的事，带日期，最多 8 条 | `data\memory\groups\群号.json` |

- **怎么形成的**：
  - 每轮对话先攒起来。
  - 攒够 8 条（`MEMORY_BATCH`，约 4 轮）后，在后台调用一次模型整理进档案、评估好感，不影响回复速度。
  - 整理时不记隐私（手机号、住址、证件等）和敏感信息（健康、政治、宗教等）。
- **怎么用的**：谁在跟她说话，就带上谁的档案；在群里再加上本群往事。都作为提示给模型，让她自然地用上，不会逐条念出来。
- **管理员指令**（群里要先 @ 她）：
  - `/记忆 @某人`（或 `/记忆 QQ号`、`/记忆 我`、`/记忆 本群`）：查看她记住了什么。
  - `/忘记 @某人`（或 QQ号、我、本群）：删除对应的长期记忆。
- **`/重置` 只清短期记忆**：群里只有管理员能用，私聊每个人都能清自己的。重置时，还没整理的旧消息也会一起丢掉，免得把聊歪的内容记进档案。

### 5.4 伊蕾娜人设（`personas\elaina.md`）

- **身份**：她以第一人称把 24 卷的经历当作自己的旅途回忆。群聊被设定成"用传信魔法和旅途中结识的人通讯"，所以不会出戏。
- **内容**：
  - 基本资料
  - 性格
  - 喜好和雷点
  - 说话方式
  - 主要角色速查（外貌、喜好）
  - 旅途总览
  - 示例台词
- **核对**：所有事实都按原文逐条核对过。
- **防编造**：人设里有一条规定，说到别人的外貌和喜好，只能说资料里写明的内容。

### 5.5 小说知识库

- **三个来源**：
  - `knowledge\characters.md`：42 个角色的档案，已按原文核实。
  - `knowledge\summaries`：24 卷逐章摘要，共 312 条。
  - `novel\*.txt`：原文，切成约 5000 段。
- **话里点名某个角色**：带上这个角色档案的关键部分，包括外貌、说话方式、喜好、常见误解。
- **其余检索**：检索摘要和原文，只在相关度够高时才带，每次最多 2 条摘要、1 段原文。
- **追问**：像"那后来呢""她是谁"这样的追问，会把双方上一句一起拿去检索。

### 5.6 防出戏

- **提示词**：明确告诉她，她是这个世界里真实的魔女，不知道服务器、AI、机器人、动漫、角色扮演这些概念。有人这么说她，就当成听不懂的外国话岔开。
- **发出前检查**：回复里出现这类词，而且不是对方自己刚说过的，就让她以伊蕾娜的身份重说一遍（多花一次调用）。重说后还出戏，就删掉出戏的那几句，删光了就不发。
- **日志**：控制台会记下“回复出戏，重新生成”，方便你看到底发生了多少次。

### 5.7 出错时

- **不发任何消息**：DeepSeek 调用失败时，群里和私聊都不发任何东西，旧版的"信号不太好"已经去掉。这一条也不会写进记忆。
- **私信提醒管理员**：余额不足、API Key 失效、或者没配置 Key 时，会私信管理员（`SUPERUSERS`）。同一类问题 1 小时内只提醒一次（`ADMIN_ALERT_INTERVAL`）。**前提是管理员的 QQ 和机器人小号是好友**，否则私信发不出去，只能在控制台里看到。
- **其他错误**：比如网络超时，只记在控制台日志里，不打扰管理员。

### 5.8 省 token 的设计

| 做法 | 效果 |
|---|---|
| 人设固定放在最前面 | DeepSeek 对重复的开头按缓存价计费，人设这部分几乎不花钱 |
| 短期记忆：群 10 条 / 私聊 20 条 | 每次请求的上下文短 |
| 日常闲聊约 10～30 字、上限 80 token | 输出费用低 |
| 对方消息超过 300 字就截断（`MAX_INPUT_CHARS`） | 防止有人贴长文刷费用 |
| 旁听最多暂存 5 条（`PASSIVE_BUFFER`） | |
| 回忆资料压缩：角色档案只带关键部分、原文只带 1 段 | 触发检索时，资料大约减少一半 |
| "没 @ 也回复"的判断只在提到她、或正在和她聊时才做，每次约 200 token | 普通群聊不花钱 |
| 长期记忆每 8 条旧消息整理一次 | 摊到每条消息上，开销很小 |

- **费用参考**：小群日常聊天，一个月通常只要几块钱。
- **换更强的模型**：想让伊蕾娜更聪明，可以改成 `deepseek-v4-pro`，价格约为 4 倍。

### 5.9 好感度（对陌生人冷淡，对熟人随意）

- **分数**：每个人（按 QQ 号，群聊和私聊共用）有一个好感分，范围 -100～100，新人从 0 开始。

| 档位 | 分数 | 她的态度 |
|---|---|---|
| 讨厌 | 低于 -20 | 爱答不理，回得极短（“哦。”“有事？”）；有 40% 的概率直接不理，不花 token |
| 陌生人 | -20～29 | 冷淡疏离；告白、调情直接怼（“蛤？你脑子没问题吧？”） |
| 熟人 | 30～69 | 随意，偶尔毒舌；告白就说“我打飞你哦” |
| 很熟 | 70 以上 | 嘴硬里带点在意（**只有确认是女生才能到这一档**） |

- **性别限制**：男生和没确认性别的人，好感最高 69 分（熟人）。确认是女生后才能继续涨到很熟。
  - 她**不会主动问**性别。
  - 长期记忆整理时会根据自称、说话方式、昵称**初步猜**一下，只作参考：不说破、不解锁很熟。
  - 对方自己说“我是女生 / 本人男”之类的，她会先质疑一句（“真的假的？”）；对方在 30 分钟内再确认（“真的”“骗你干嘛”或再说一遍），才算数。说“开玩笑的”就作罢；以后改口，她会再质疑一次。
  - 管理员可以用 `/性别 @某人 女`（或 `男`、`清除`）直接设置；`CLOSE_FRIENDS` 里的人不受性别限制。

- **分数怎么变**：
  - **正常聊天**：不加分，好感只看聊了什么（想恢复“每聊一次 +1、每天最多 +5”，设 `AFFECTION_CHAT_GAIN=1`）。
  - **看聊天内容**：长期记忆每攒够 8 条对话会整理一次，整理时顺便站在伊蕾娜的角度给每个人打分。
    - 聊得投机、尊重她、真诚关心她、请她吃面包：+1～+5
    - 纠缠、刷屏、强加称呼或关系、提蘑菇：-1～-5
    - 拿身材开玩笑：-3～-8
    - 辱骂、骚扰：-6～-15
    - 以上是对陌生人的标准。整理时会告诉模型每个人现在的档位：熟人之间的调侃、互损只算 0～-2；很熟的人开玩笑、玩身材梗基本不扣，真心关心可以多加；讨厌的人冒犯扣得更重，加分减半。
    - 这一步本来就在做，几乎不多花 token。
  - **雷点词立刻扣分**：消息里出现“平胸、飞机场、贫乳、洗衣板”等词时当场扣分，不调用模型。扣多少看关系：

| 档位 | 每次 | 每天最多 |
|---|---|---|
| 讨厌 | -6 | -24 |
| 陌生人 | -4 | -16 |
| 熟人 | -2 | -8 |
| 很熟 | -1 | -4 |

  - **时间**：7 天不聊开始回落，每天向 0 靠 2 分。好感会淡，讨厌也会淡。
- **旧数据**：以前只按说话次数计数的人，会按次数给一个初始分，最多 25 分。
- **管理员指令**：
  - `/好感 @某人`（也可以写 QQ 号、“我”）：查看分数、档位和最近 5 次变化的理由。
  - `/好感 @某人 +10`、`-10`、`=50`：手动调整。
  - `/性别 @某人`：查看；后面加 `男`、`女`、`清除` 来设置。
  - `/记忆 @某人`：也会显示好感分。
  - `/忘记`：只删印象，不清零好感。
- **可调项**：`AFFECTION_DISLIKE`、`AFFECTION_ACQUAINTANCE`、`AFFECTION_CLOSE` 调档位门槛，`DISLIKE_IGNORE_PROB` 调不理人的概率，`CLOSE_FRIENDS=[QQ号]` 直接设为很熟。`TABOO_WORDS` 改雷点词表，`TABOO_PENALTY` / `TABOO_DAILY_MAX` 设陌生人的扣分标准，`TABOO_TIER_MULTIPLIER` 设各档倍数（设为 0 就是这一档不扣）。
- **第三人称不接话**：有人用“她”向别人介绍她时，判断规则会让她不接话。

### 5.9b 时间感：知道隔了多久

- 每条聊天记录都带时间。上一段聊天已经过了 3 小时以上时，会提醒她这是新的一段对话，别硬接旧话题。
- 对方隔了 6 小时以上才来找她，会告诉她隔了多久，她按关系决定提不提：
  - 陌生人、讨厌：不提。
  - 熟人：3 天以上，随口一句“好久不见”。
  - 很熟：1 天以上，可能嘴硬地吐槽一句“这几天跑哪去了”；7 天以上会更在意一点，但嘴上不承认。
  - 她寄过信而对方一直没回：可能顺口问一句收到没有。
- 可调项：`GAP_NOTICE_HOURS`、`CONTEXT_STALE_HOURS`。

### 5.9c 主动写信

- 只写给**很熟**的人，而且必须是机器人的 **QQ 好友**，用私聊发（不在群里发，免得触发风控）。
- 条件：对方至少 24 小时没来找她；距离上一封信至少 3 天；上一封信没回就不再写。
- 每个符合条件的人每天大约 25% 的概率收到信；所有人合计每天最多 3 封。只在北京时间 10:00～22:00 寄，高峰时段不寄。
- 信的内容：写她旅途中的见闻，顺带提一句和对方有关的事，60～150 字，开头“致 某某：”，结尾“——伊蕾娜”。每封信调用一次模型。信会记进和对方的私聊记忆里，对方回信时她知道在回什么。
- 管理员指令：
  - `/写信 @某人`（或 QQ 号、我）：马上写一封，用来测试。不看好感和时间，但对方必须是好友。
  - `/写信 检查`：看看谁是很熟、现在符不符合条件、今天寄了几封。
- 可调项：`LETTER_ENABLED`、`LETTER_DAILY_PROB`、`LETTER_MIN_DAYS`、`LETTER_MIN_SILENCE_HOURS`、`LETTER_HOURS`、`LETTER_MAX_PER_DAY`。

### 5.10 DeepSeek 高峰时段（她“很忙”）

- **时段**：北京时间周一至周五 9:00-12:00、14:00-18:00，不含法定节假日。2026 年的放假日期已经内置；2027 年起的日期需要在 `PEAK_HOLIDAYS` 里补上。
- **高峰时她这样表现**：
  - 不主动接话，没 @ 就不回，也不做判断。
  - 被叫到时，每人每 10 分钟最多一次正经回复。正经回复只说 10～20 字，也不检索小说。
  - 其余时候，一半概率只回一句“在忙，晚点。”这类固定台词，不调用模型，零花费；已经回过“在忙”的人再叫，就干脆不回。
  - 回复前会多等 5～20 秒，显得在忙。
  - 长期记忆的整理推迟到低峰时段再做。
- **关闭**：`PEAK_ENABLED=false`。

### 5.10b 限额用完时的告别

- **告别**：每小时的回复限额（全局 60 条、每群 20 条；每群的代码默认是 40 条）用完那一刻，她会在最后补一句告别，比如“好了，我该上路了。”“我要去下一个国家了，有缘再见。”，让大家知道她接下来一段时间不会回。
- **不花钱、不重复**：这句是固定台词，不调用模型。同一个群一小时只说一次。
- **什么时候恢复**：限额按滑动的一小时计算，最早那几条满一小时后，她就会重新回复。
- **关闭**：`FAREWELL_ON_LIMIT=false`。

### 5.11 识图

- **原理**：分两步。
  1. **认人（本机，免费）**：用 WD14 Tagger 看图里是不是动漫角色。这类模型是按 Danbooru 图站的标签训练的，同人图、表情包里的伊蕾娜都认得出来。一张图大约 1 秒，只占 2 个 CPU 核（`VISION_TAGGER_THREADS`）。
  2. **写描述**：把图交给 `deepseek-flash`，写成一句不超过 50 字的描述，比如“[图片：一只橘猫趴在键盘上]”。第 1 步认出是伊蕾娜时，会告诉模型，描述就写成“[图片：伊蕾娜本人的画像，戴着魔女帽一脸嫌弃，配字‘嫌弃’]”。
- **她看到自己的画像**：人设里加了“看到自己的画像”一节。她只当是有人给她画的，按自恋、嘴硬的性格反应：画得好就理所当然收下夸奖，画成怪表情就吐槽画的人；配字是在表达情绪，就顺着那个情绪回。同一张画反复出现，她会说“又是这张？”。
- **没 @ 也可能搭话**：群里有人只发了一张她的图，她也可能说一句。规则见 5.1 的表格。可调项：`VISION_SELF_REACT`（开关）、`VISION_SELF_REACT_PROB`（概率，默认 0.6）、`VISION_SELF_REACT_INTERVAL`（间隔秒数，默认 600）。关掉 `SMART_REPLY` 时这项也不生效。
- **不出戏的措辞**：描述里的“动漫”“二次元”“角色”等词会自动换成“画中人”“插画风格”，免得她说出这些词、触发防出戏重写。
- **只认得伊蕾娜**：模型的词表里，《魔女之旅》只有伊蕾娜一个角色，沙耶、芙兰等人认不出来，只会按外貌描述。别的作品的角色（比如初音未来）模型认得，但描述里不写名字，因为伊蕾娜不认识她们。
- **引用图片**：引用一张图再 @ 她（比如“这是什么”），她也会去看被引用的那张。
- **缓存**：同一张图只看一次，表情包被反复发也不重复花钱，缓存在 `data\vision_cache.json`。升级到 v4 时旧缓存会自动作废，因为以前的描述认不出人。角色识别模型还没准备好时看过的图，等模型准备好后再遇到，会重新看一遍。
- **进入记忆**：描述会写进聊天记录，所以接着问“你觉得它可爱吗”也能接上，长期记忆也能用到。
- **费用**：认人不花钱。写描述每张图最多约 1000 个输入 token，大约 0.1～0.2 分钱。
- **高峰时段**：默认不调用 DeepSeek 看图（`VISION_IN_PEAK=false`），但本机认人照常：被 @ 时如果图里是她，她会看到“[图片：伊蕾娜本人的画像]”；其他图只显示“[图片]”。高峰时段没 @ 她就不会搭话。
- **设置**：`VISION_ENABLED=false` 关掉整个识图；`VISION_TAGGER=false` 只关认人；`VISION_MAX_IMAGES` 设一条消息最多看几张图（默认 2）。看图固定用 `deepseek-flash`，因为 `deepseek-v4-pro` 不支持图片，所以你把聊天模型换成 pro 也不影响看图。
- **认错或认不出**：调 `VISION_TAGGER_THRESHOLD`（默认 0.75）。把别人认成伊蕾娜就调高到 0.85，她自己的图认不出就调低到 0.6。控制台里的“角色识别：elaina_(majo_no_tabitabi)（0.93）”这类日志会显示每张图的置信度。想更准可以把 `VISION_TAGGER_REPO` 换成 `SmilingWolf/wd-eva02-large-tagger-v3`（约 1.2 GB，更慢）。
- **半确定的图再确认一次**：伊蕾娜的置信度在 `VISION_TAGGER_MAYBE`（默认 0.35）到门槛之间时，多半是她穿便服、没戴帽子的图。这时会提示 deepseek-flash“可能是伊蕾娜，请仔细看”，它确认了才算，日志里会写“（看图模型确认是伊蕾娜）”。不多花钱，这一步本来就要看图。设成 1 就关掉。只有被 @、要写描述时才会再确认；没 @ 时的搭话只看本机识别。
- **管理员手动纠正（`/认图`）**：引用一张图，@ 她并发送：
  - `/认图`：看她认出了什么，包括置信度、结论和她看到的描述。
  - `/认图 是`：以后这张图就当成她自己。同一张图在 QQ 里重发、当表情包用都算。
  - `/认图 不是`：以后不当成她。`/认图 取消`：恢复自动识别。
- **测分数（`识图测试.bat`）**：把一张或几张图片拖到 bot 文件夹里的 `识图测试.bat` 上，会列出每张图最像的 5 个角色、伊蕾娜的置信度，以及按现在的门槛会怎么处理。不连 QQ、不花钱，适合用来调门槛。
- **没看成**：图太大（超过 5MB）、下载失败或格式不认识时，她只会看到“[图片]”，会直说没看清。

#### 第一次启动（升级到 v4 后）

1. 双击 `start.bat`。它发现依赖有更新，会先自动安装 `onnxruntime`、`numpy`、`Pillow`（从清华镜像，约 1 分钟）。
2. 机器人启动后，会在后台下载角色识别模型（约 470 MB）。先从 hf-mirror.com 下载，失败了再试 huggingface.co。控制台每下完 10% 提示一次，下载期间聊天和识图照常，只是还认不出人。
3. 看到 `角色识别：已启用（……认得伊蕾娜……）` 就好了。
4. 下载中断没关系，下次启动会接着下。一直下不下来的话，可以用浏览器从 `https://hf-mirror.com/SmilingWolf/wd-swinv2-tagger-v3/tree/main` 手动下载 `model.onnx` 和 `selected_tags.csv`，放进 `D:\QQBot\bot\data\models\wd-swinv2-tagger-v3\`。

### 5.13 发表情包

- **表情从哪来**：小号 QQ 的收藏表情（"爱心"里的）。连上 QQ 后自动拉取，之后每 6 小时拉一次，下载到 `data\stickers\`，同一张图只存一份。你在手机上收藏或取消收藏，下次拉取时自动同步；取消收藏的不会再发。
- **每张表达什么情绪**：新表情会交给 deepseek-flash 看一次，从这 10 个情绪里选 1～2 个：得意、嫌弃、无语、生气、开心、害羞、疑惑、委屈、震惊、敷衍，再写一句描述（包括配字）。每张只看一次，约 0.1～0.2 分钱。高峰时段不看，等低峰再看。
- **什么时候发**：
  - 每次回复前程序先抽签，约 15% 的概率这一轮可以带表情（`STICKER_PROB`）。抽中了才告诉她"这轮可以甩一张"，以及库里现在有哪些情绪；她觉得合适就在回复末尾写 `[表情:嫌弃]`，程序截掉标记，挑一张对应情绪的表情发出去。不多花调用。
  - 同一个群（私聊按人）两次表情至少隔 3 分钟（`STICKER_MIN_INTERVAL`）；最近发过的 5 张不重复。
  - **只发表情**：抽中表情、这轮又刚好是"只回几个字"时，有一半概率提示她可以只甩一张表情、不说话。仍然调模型，所以表情和话题对得上。
  - **斗图**：有人发了她的画像（5.11 认出来的），这一轮带表情的概率提高到 50%（`STICKER_SELF_REACT_PROB`）。
  - **按关系**：讨厌的人概率 ×0.5，只能收到嫌弃、无语、敷衍；陌生人 ×0.7，不会收到害羞、委屈；熟人 ×1；很熟 ×1.3。
- **怎么发**：先发文字，隔一两秒再发表情。只发表情时，如果中间有人插话，就引用原消息。表情计入每小时限额；限额只剩最后一条时不发表情。
- **在她眼里**：人设里加了"甩小画像"一节，她随身带着一叠用魔法画的自己的小画像，偶尔甩一张过去。聊天记录里写成"[发了表情：嫌弃（叉腰斜眼，配字'哈？'）]"，对方问"你这什么表情"她也接得上。长期记忆不记这些。
- **写信、空间评论不发表情**：模型要是写了表情标记，会自动去掉。
- **管理员指令**（群里先 @ 她）：

| 指令 | 作用 |
|---|---|
| `/表情` | 概况：可用几张、每种情绪几张、缺哪些情绪 |
| `/表情 列表` | 列出每张的编号、情绪、描述（✎ 表示手动改过） |
| `/表情 3` | 把 3 号发出来看看 |
| `/表情 3 嫌弃 无语` | 手动改标签，以后刷新也不会覆盖 |
| `/表情 3 禁用` / `/表情 3 启用` | 停用或恢复一张 |
| `/表情 刷新` | 马上重新拉收藏 |
| `/表情 测试 嫌弃` | 按情绪挑一张发出来 |

- **可调项**：`STICKER_ENABLED`（开关）、`STICKER_PROB`、`STICKER_MIN_INTERVAL`、`STICKER_ONLY_PROB`、`STICKER_SELF_REACT_PROB`、`STICKER_RECENT_AVOID`、`STICKER_REFRESH_HOURS`、`STICKER_PRIVATE`（私聊发不发）、`STICKER_TIER_MULTIPLIER`（各档倍数）。
- **显示样式**：默认 `STICKER_SUB_TYPE=1`，让它在 QQ 里显示成表情样式（小图）。如果发出来显示不对或发不出去，改成 `-1`，按普通图片发。
- **某种情绪一直发不出来**：看 `/表情` 里有没有这种情绪。每种情绪最好收藏 2～3 张。

#### 第一次启动（升级到 v5 后）

1. 确认小号收藏表情里已经存好伊蕾娜表情。
2. 重开 start.bat。连上 QQ 约 15 秒后，日志会出现"表情：收藏 N 张，新增 N……"，接着逐张出现"表情：1 号 → 嫌弃、无语｜……"。高峰时段要等到低峰才打标签。
3. 打完后 @ 她发 `/表情 列表` 抽查一下，标错的用 `/表情 编号 情绪` 改掉。
4. @ 她发 `/表情 测试 得意`，看看发出来是不是表情样式、动图能不能动。

### 5.14 QQ 空间日记

详细设计、接口和测试记录见《QQ空间日记功能方案.md》，这里只写怎么用。

- **每天一条说说**：北京时间 20:30～22:30 之间随机一个时刻（每天早上定好，重启不变），发 1 张图库里的伊蕾娜图 + 一段文案，所有人可见。
  - **文案素材**是当天的聊天：白名单群全算，私聊只算有长期档案的人。20:00 先做一次“日结”，把白天还没整理的聊天整理成“今日见闻”。
  - **按好感度挑见闻、定写法**：很熟的人可能被“认出来”，陌生人写成“新认识的人”，讨厌的人偶尔被吐槽。文案里不会出现非“很熟”的人的昵称。
  - **篇幅每天随机**：一句话、两三句、小游记（100～200 字）。
  - **配图**：按见闻关键词和季节从图库挑，60 天内不重复。图放在 `bot\qzone\images\`，程序会自动压缩（原图不动）、认人、看图打标签。现在 20 张，大约 20 天后开始重复，建议慢慢补到 60 张以上。
  - 发布失败隔 10 分钟再试，最多 3 次；都失败就私信管理员。
- **回复评论**：自己最近 7 天说说下的评论，直接对她说的就按聊天规则回（好感、长短、出戏检查、雷点扣分都一样）；别人之间聊天不插嘴；超过 24 小时的不补回；同一个人同一楼最多来回 3 轮。
- **回复别人空间里的 @**：别人在自己的说说里 @ 她、在说说下 @ 她或回她，也按聊天规则回（`QZONE_MENTION_REPLY`）。同一个人连着 @ 几次，合成一次回。
- **节奏**：9:00～次日 1:00 每 2 小时查一轮（1:00～9:00 不查，像在睡觉）；每轮最多回 2 条，两条之间隔 2～5 分钟；每天最多回 10 条（评论和 @ 合计）。
- **在她眼里**：有人在聊天里提到她的说说，她知道自己写过什么；空间里的对话也记进记忆。
- **管理员指令 `/说说`**（私聊直接发，群里先 @ 她）：

| 指令 | 作用 |
|---|---|
| `/说说 预览` | 马上生成一条给你看，不发布 |
| `/说说 发预览` | 把 2 小时内预览的那条发出去，今天不再定时发 |
| `/说说 立即发` | 马上生成并发出，今天不再定时发 |
| `/说说 删除最新` | 删掉她最近发的一条 |
| `/说说 今日` | 今天几点发、发了没有、回了几条、有没有熔断；列出今日见闻 |
| `/说说 图库` | 处理新图，显示图库情况 |
| `/说说 查评论` | 马上查一轮评论和 @ 并回复 |
| `/说说 日结` | 马上把今天的聊天整理成见闻 |
| `/说说 暂停` / `/说说 恢复` | 停掉或恢复自动发说说和回复；`恢复` 同时解除熔断 |

- **开关**：`QZONE_ENABLED=true`（代码默认关，所以 `.env` 里这一行不能删）。临时停用发 `/说说 暂停`，不用重启。
- **`/空间测试`** 是开发时的探路指令，探路插件（`plugins\qzone_probe\`）删掉后就不能用了，不影响正式功能。

### 5.15 空间风控保护

9/26 19:37 小号被下线后加的（来龙去脉见《风控记录.md》#2）。

- **熔断**：空间任何接口返回限流码（`-10049`“使用人数过多”“操作过于频繁”等）、验证页面或 403 时：
  - 这一轮剩下的操作立刻停；
  - 空间功能（发说说、回评论、回 @）全部停 24 小时（`QZONE_RISK_PAUSE_HOURS`），**聊天不受影响**；
  - 私信管理员：原因、停到几点、怎么提前恢复；
  - 熔断期间 `/说说 发预览`、`立即发`、`删除最新`、`查评论` 会被拦下；`/说说 今日` 会显示熔断到几点。
  - 到点自动恢复；想提前恢复发 `/说说 恢复`，先确认小号没有异常。
- **降频**：查评论从每 30 分钟改成每 2 小时；每天最多回复从 30 条改成 10 条；每轮最多 2 条、间隔 2～5 分钟；空间凭证用到失效才重新向 NapCat 要（以前每 30 分钟要一次）。
- **回复没确认发出，就不记进记忆、也不算回过**，免得她以为自己说过。也不重试，免得其实发出去了又重复发。
- **风控事件记录 `bot\data\risk_events.log`**：机器人连上、断开 NapCat（断开那行会附上最近一小时回了几条、最近一次空间写操作是什么时候）、NapCat 报告账号下线、空间风控信号、熔断和解除。**出事后先看这个文件**，再把结论记进《风控记录.md》。
- **NapCat 文件日志**建议打开（`NapCat.Shell\config\napcat_<小号QQ号>.json` 里 `"fileLog": true`），日志在 `NapCat.Shell\logs\`，下线时能查到 QQ 那边的提示。
- **如果又熔断**：第一个考虑关的是回复 @（`QZONE_MENTION_REPLY=false`）。

## 6. 迁移到服务器

1. 在服务器上用 Docker 部署 NapCat（`mlikiowa/napcat-docker`），WebUI 的配置方法和上面一样。
2. 把整个 `D:\QQBot\bot` 和 `D:\QQBot\novel` 一起拷过去，保持两者的相对位置不变。`data\history`（短期记忆）、`data\memory`（长期记忆）、`data\stickers`（表情库）、`data\qzone`（发过的说说和评论已读记录，不带会重复回旧评论）、`qzone\images`（图库）都要一起带走。然后执行 `python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python bot.py`，建议用 systemd 让它常驻。
3. 换机器登录相当于"异地登录"，是封号的高发时刻。建议先在服务器上正常登录那个小号用几天，再挂机器人。
4. 如果 NapCat 和 NoneBot 不在同一台机器上：`HOST` 改成 `0.0.0.0`，URL 改成对应的 IP，token 换成一串随机字符（不要带 QQ 号）。

## 7. 常见问题（含本次部署实际遇到的）

| 现象 | 原因与解决 |
|---|---|
| NapCat 一键包报"HTTP 404，下载QQ失败" | 内置的 QQ 下载地址失效了。改用"手动装 QQ + NapCat.Shell.zip"（见 4.2） |
| `[Errno 10048] … 8080` | 端口被占用（常见是 Steam）。改用 8081，NapCat 和 `.env` 两边都要改 |
| WebUI 要 token | 看 NapCat 日志里的 `WebUi Token`，或者 `config\webui.json` |
| 设了快速登录，还是每次都要扫码 | 看 NapCat 日志：<br>• `没有 -q 指令指定快速登录`：`-q` 参数没传到（这个版本的启动器不转发它）。改用 `webui.json` 里的 `autoLoginAccount`（见 4.2）<br>• `快速登录失败，未找到该 QQ 历史登录记录`：本机没有这个号的记录，先扫码登录一次<br>• `你的用户身份已失效，为保证账号安全，请你重新登录`：凭证在腾讯那边被作废了，常见于被风控下线之后（9/26 那次就是）。这次只能扫码，扫完之后自动登录就恢复正常 |
| 快速登录列表里出现了大号 | 正常：列表读的是这台电脑上 QQ 的本地登录记录，大号在这台电脑上登过就会出现，NapCat 没有去查或登录大号。务必在 `autoLoginAccount` 里指定小号（见 4.2）。平时不在这台电脑上用大号的话，可以在 QQ 登录界面把大号头像移除 |
| 新建连接时表单里有 Host/Port、没有 URL | 选成了 Websocket Server，要选 **Client** |
| 启动报 `error parsing env var "nickname"` | 写成了 `NICKNAME=[伊蕾娜小姐]`，要写成 `NICKNAME=["伊蕾娜小姐"]` |
| 她突然不回话了 | 多半是 DeepSeek 调用失败：看控制台里的"DeepSeek 调用失败"日志。余额不足或 Key 失效时，管理员会收到私信 |
| 管理员没收到私信提醒 | 管理员大号要和机器人小号互加好友 |
| NapCat 突然要求重新登录（手机没有风控提示、也没在别处登录） | 多半是短时间发言太多（《风控记录.md》#1）。扫码重登即可。现在的限速：全局每小时 60 条、每分钟 8 条，每群每小时 20 条，“没 @ 也回复”每群至少间隔 120 秒，打字延迟按字数算。还不放心就把 `GLOBAL_RATE_PER_HOUR` 调到 30、`GLOBAL_RATE_PER_MINUTE` 调到 4 |
| 设备被下线，风险类型是“设备存在外挂或其他软件影响QQ正常使用” | NapCat 被识别出来了（《风控记录.md》#2）。等半天到一天再扫码；把 NapCat 和 QQ 更新到互相匹配的版本；别同时开其他会注入 QQ 的工具。先看 `data\risk_events.log` 和 `NapCat.Shell\logs\`，把经过记进《风控记录.md》 |
| 私信收到“QQ 空间功能熔断”的提醒 | 空间接口返回了限流或验证，空间功能自动停 24 小时，聊天照常（5.15）。一般等它自己恢复；确认小号正常后也可以发 `/说说 恢复`。频繁熔断就先关回复 @：`QZONE_MENTION_REPLY=false` |
| 她不发说说、也不回空间评论了 | 发 `/说说 今日` 看看：是不是熔断中、暂停了，或者今天的 10 条回复额度用完了；再看 `.env` 里 `QZONE_ENABLED` 是不是 `true` |
| 她在群里插话太多 | 调大 `SMART_MIN_INTERVAL`（现在是 120 秒），或者设 `SMART_REPLY=false` |
| 她记错了某人的事 | 管理员发 `/记忆 @那人` 查看，发 `/忘记 @那人` 删除 |
| 回复又变长了 | 长回复上限是 `LONG_REPLY_MAX_TOKENS`（默认 200）、闲聊是 `SHORT_REPLY_MAX_TOKENS`（默认 80）；旧的长回复还留在短期记忆里时可以 `/重置` |
| 一直没有 `Bot connected` | 端口和 token 两边是否一致；连接是否启用；是否等够了 30 秒 |
| @ 了没反应 | 群号不在白名单里，或者触发了冷却（日志会显示"限流跳过"） |
| 人设换了但她还用旧身份说话 | @ 她发 `/重置`，清掉旧记忆 |
| 她老是扯到小说、或者从不提小说 | 调高或调低 `KNOWLEDGE_MIN_*_SCORE`；日志里的"回忆命中"会显示每次带了哪些内容 |
| 知识库没加载 | 看启动日志；确认 `D:\QQBot\novel` 下有 txt |
| 日志里有“角色识别：缺少依赖” | 依赖没装上。关掉机器人窗口，重新双击 start.bat；还不行就在 bot 文件夹里运行 `.venv\Scripts\pip install onnxruntime numpy Pillow -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 日志里有“角色识别：……下载失败” | 网络连不上模型站。下次启动会自动接着下，或者按 5.11 的第 4 步手动下载 |
| 发了伊蕾娜的图，她还是没认出来 | 先看日志里有没有“角色识别：已启用”。有的话看那张图的置信度，低于门槛就把 `VISION_TAGGER_THRESHOLD` 调低。Q 版、剪影、只画背影的图本来就很难认 |
| 她老把别的银发角色认成自己 | 把 `VISION_TAGGER_THRESHOLD` 调高到 0.85 |
| 群友拿她的表情包斗图，她搭话太多 | 调大 `VISION_SELF_REACT_INTERVAL`、调低 `VISION_SELF_REACT_PROB`，或者设 `VISION_SELF_REACT=false` |
| 日志里有"表情：收藏表情是空的" | 小号收藏里没有表情，或者 NapCat 版本太旧、不支持 `fetch_custom_face`：升级 NapCat |
| 她从来不发表情 | 发 `/表情` 看可用几张；0 张就先 `/表情 刷新`。有表情但很少发，就调高 `STICKER_PROB` |
| 表情发出来是大图、或者发送失败 | `.env` 里设 `STICKER_SUB_TYPE=-1`，按普通图片发 |
| 表情和话题对不上 | `/表情 列表` 看是不是标签打错了，用 `/表情 编号 情绪` 改 |
