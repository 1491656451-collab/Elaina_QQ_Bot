## 2. 为什么会混

1. **两段经历名字都带“梦”**：人设的“旅途回忆总览”第17条“梦回之城卡尔赛尔”和第24条“宁梦璃的梦境国度”，模型把地名和人拼错了。
2. **第一句时检索没帮上忙**：13:04 这句话查到的只有“第4卷·忘却之都”（第一次认识艾姆妮西亚），没有第24卷，她只能靠人设总览回忆。
3. **说错一次，后面顺着错**：13:05 检索其实带上了艾姆妮西亚的角色档案（里面写着第24卷梦境国度），但聊天记录里已经有她自己说的“梦回之城”，她顺着自己的话讲了卡尔赛尔的故事。13:06 对方追问，她才按档案说对，但没改口。

## 3. 这次的改动

| 改动 | 说明 |
|---|---|
| **记混检查**（新文件 `plugins\roleplay_chat\factcheck.py`） | 不调用模型。开机时查出每个地方、每个角色出现在哪几段经历：地方看章节摘要的“地点”“经过”、卷概要；角色看“登场”“本卷重要角色”、角色档案里引用的卷数；两边都加上人设总览那一条。只是“本卷提到她”的不算（第17卷摘要里有一句“伊蕾娜联想到艾姆妮西亚”，不算她在那一段）。回复里**同一句话**提到某个地方和某个角色，两者没有一段重合，就算记混了 |
| 记混了就重说 | 告诉她哪里混了：那个地方是哪段经历（附总览那一条）、那个人真正和她有交集的几段（取角色档案“与伊蕾娜”，优先放最近的）。重说一次；还混就删掉那几句，删光了就说“那段我记不太清了”。说错的那句不进聊天记录 |
| 不误伤 | 否定、假设、联想、比较、听说的句子不查（“不是在卡尔赛尔”“让我想起艾姆妮西亚”“要是……”）；分在两句话里的不查；伊蕾娜自己、扫帚不查 |
| 地名表（新文件 `knowledge\places.md`） | 62 个有辨识度的专名（卡尔赛尔、伊斯特、宁梦璃之国……），一行一个，别名用 `|` 隔开。出现在哪几段由程序自动算，不用手写。“某国”“森林”这种不收 |
| 人设 | 旅途总览后面加一句：几段带“梦”的经历别记混（恶魔造的梦 / 梦里的法庭 / 梦回之城是重复同一天、不是做梦 / 宁梦璃的梦境国度才是和艾姆妮西亚重逢的地方），人和地方要对得上，拿不准是哪一段就别说地名 |
| 回忆规则 | 加一条：回忆片段和她自己上面说过的话对不上时，以片段为准，自然地改口（“啊，不对，是在……”），别顺着说错的继续编 |
| 开关 | `FACT_CHECK=true`（默认开）；地名表路径 `KNOWLEDGE_PLACES_FILE` |

- 13:05、13:06 那两句（各自是对的）：不报。

## 5. 还做不到的，和以后可以做的

| 情况 | 现在 | 以后可以怎么做 |
|---|---|---|
| 地名和人不在同一句（“我在梦回之城待了很久。艾姆妮西亚也在。”） | 不查 | 可以放宽到相邻两句，但误报会多，先看这次的效果 |
| 两个角色拼错（“安妮洛特和艾姆妮西亚一起……”） | 不查 | 人和人的组合误报更多（比如“她让我想起芙兰老师”），暂不做 |
| 事件细节编错，但人和地方都对（结局说反、谁说了什么） | **13:48 起：讲长故事时再调一次模型核对**（见第 6 节） | |
| 地名表里没有的地方 | 不查 | 往 `knowledge\places.md` 里加一行就行 |
| 写信、主动搭话、空间回复、说说 | 不查（这次只接了聊天回复） | 说说和空间回复可以接同一个检查，改动小 |
| 第一次问起时检索没带上最相关的那段（这次只查到第4卷） | 靠人设总览 | 问“以前的朋友”“遇到过谁”这类话时，可以按提到的角色把档案的“与伊蕾娜”那段带上；这次对方没点名，要从她自己的回复里反查，就是现在的记混检查在做的事 |

## 6. 13:48 补充：讲长故事时再核对一遍

你同意了“讲长故事时再调一次模型核对”，已经加上：

| 项目 | 说明 |
|---|---|
| 什么时候核对 | 回复至少 40 字（`STORY_CHECK_MIN_CHARS`），而且在讲往事：这一轮带了回忆资料，或者回复里提到了小说里的人 / 地方。闲聊、短回复不核对。高峰“很忙”时不核对 |
| 拿什么核对 | 这一轮带给她的回忆片段；回复里提到的人的角色档案（最多 2 人）；回复里提到的地方那几段经历（人设旅途总览的原话）；按回复内容再查的摘要（最多 2 条，够相关才带）。合计最多约 3500 字 |
| 怎么判 | 另开一次对话问模型：回复里的往事和资料有没有**矛盾**（张冠李戴、地点错、两段拼在一起、谁做了什么说反、结局错）。资料里没写的细节、她的感想和语气、玩笑夸张都不算错；拿不准算没问题。只输出 JSON |
| 讲错了怎么办 | 把“哪里错了、资料里其实是怎样”告诉她，重说一次；重说后不再核对第二遍（省钱），但会再过一遍记混检查。说错的那版不进聊天记录 |
| 出错时 | 核对这一步超时、报错，就照原样发，不影响回复 |
| 花费 | 每次约 0.002 元（资料 2000 token 左右，基本不命中缓存），算进聊天的钱里；`/花费` 里单独一行“核对讲的往事”。按每天 150～250 轮、其中讲往事的长回复一成多算，每天大约几分钱 |
| 代价 | 讲长故事时回复会晚一两秒（核对完才开始“打字”）|
| 开关 | `STORY_CHECK=false` 关掉 |

**和记混检查的分工**：记混检查不花钱、每条都查，但只能查“人和地方对不对得上”；核对只在讲长故事时做，能查出细节说反、结局编错这类。13:04 那句“在梦回之城遇上艾姆妮西亚”只有 20 字，靠的是记混检查；13:05 那段 70 字的卡尔赛尔故事本身是对的，核对也不会拦。

**测试**：核对说没问题 → 原样发，资料里带了回忆片段和旅途总览；核对说“说反了：是伊蕾娜入梦救出艾姆妮西亚”→ 重说、发重说的版本，只核对一次；短回复不核对；核对报错照原样发；关掉开关不核对。全部 165 个测试连跑 3 遍通过。**还没在真实对话里跑过**，上线后日志里会有“讲的往事和资料对不上（……），重新生成”这样的行。
