## 0. 结论

1. **这 7 天一共花了 0.511 元，平均每天 0.073 元，没有一天花到 1.35 元。** 最多的是 10/20，0.296 元。日志里也没有一次因为钱用完停止聊天，限流全是晚上休息。

5. **聊天主模型换成 pro 以后，回消息每次大约贵 4.8 倍**（flash 每次约 0.0023 元，pro 约 0.011 元）：
   - **按这 7 天的量**：每天多花 0.15 元左右，平均每天约 0.22 元，1.5 元够用。
   - **最忙的一天（10/20）**：从 0.30 元涨到约 1.0 元，还在 1.35 元以内。
   - **每天能聊的轮数**：1.35 元从大约 350 轮降到大约 110 轮。9/29 那种量（116 次回消息）按 pro 算约 1.29 元，已经贴着线了。

## 3. 预留的 0.15 元

### 3.1 实际用了多少

预留只有在“合计花到 1.35 元、聊天停下以后”才派上用场。这 7 天聊天一次都没停，所以**预留实际一分钱没用上**。

退一步看最坏情况：就算把一整天的后台花费都算成从预留里出，最多的一天（10/20）也只有 0.081 元，还剩 0.07 元。

### 3.2 够不够

聊天停下以后，预留要付的大概是这几笔：

| 用途 | 按这几天的量 | 说明 |
|---|---|---|
| 收尾的记忆整理（没攒满的会话、20:00 日结） | 约 0.01～0.03 元 | 记忆 agent 9/30 估日结 0.02 元左右 |
| 写说说 | 约 0.001～0.003 元 | 每天 1～2 次 |
| 睡前整理（按 pro 真实价） | 每人约 0.005 元，这几天每晚 1～4 人，0.005～0.023 元 | 见下 |
| 合计 | **约 0.02～0.06 元** | 0.15 元够用 |

- **睡前整理人多了会变贵**：每晚最多整理 30 人（`memory_nightly_max`）。30 人按 pro 真实价约 0.16 元，单这一项就会超过 0.15 元。现在每晚 1～4 人，离这个数还远。
- **建议**：先不动预留。等睡前整理改成按 pro 价记账（第三批第 2 项）以后，再看每晚的真实数。经常超过 0.08 元的话，再考虑调预留，或者请记忆 agent 限制每晚人数。

## 4. 睡前整理按 pro 真实单价算

睡前整理用的是 `deepseek-v4-pro`（代码默认 `memory_nightly_use_pro=true`，日志里每晚都有“睡前整理”），但 `budget.py` 只有一张 flash 的价格表，所以是按 flash 记的账。下面用账本里的 token 数，按两种价格重算：

| 日期 | 次数（人） | 账面（flash 价） | 按 pro 真实价 | 差额 |
|---|---|---|---|---|
| 10/17 | 1 | 0.0017 | 0.0070 | +0.0053 |
| 10/18 | 2 | 0.0027 | 0.0110 | +0.0083 |
| 10/19 | 4 | 0.0050 | 0.0189 | +0.0139 |
| 10/20 | 3 | 0.0063 | 0.0226 | +0.0163 |
| 10/21 | 4 | 0.0037 | 0.0142 | +0.0105 |
| **合计** | 14 | **0.0194** | **≈ 0.074** | **+0.054** |

- **真实花费约是账面的 3.8 倍**。睡前整理大部分是没命中缓存的输入和输出，所以倍数接近输入的 4.5 倍、输出的 3.4 倍。
- **算法**：按 token 数分别算两种空闲价，取比值，再乘账面花费。账面里已经含了高峰两倍价（如果有），比值不受影响。
- **对限额的影响**：7 天少记了约 0.054 元，每天不到 0.02 元，不影响这几天的结论。
- **整理后核对**（`memory_verify`）：代码默认 `memory_verify_use_pro=false`，用的是 flash，账是对的。服务器 `.env` 有没有改成 pro，我这边看不到，请部署 agent 确认一下。改了的话，这一项也少记了约 4 倍。

## 5. 聊天主模型换成 deepseek-v4-pro 会多花多少

### 5.1 价格（元 / 百万 token，10/22 官方价）

| | deepseek-flash | deepseek-v4-pro | pro 是 flash 的几倍 |
|---|---|---|---|
| 输入，命中缓存（空闲 / 高峰） | 0.02 / 0.04 | 0.15 / 0.30 | 7.5 |
| 输入，没命中（空闲 / 高峰） | 1 / 2 | 4.5 / 9.0 | 4.5 |
| 输出（空闲 / 高峰） | 4 / 8 | 13.5 / 27.0 | 3.4 |

- **高峰时段**：工作日 9-12、14-18 点，价格是空闲的两倍，两个模型一样。
- **flash 价没变**：`budget.py` 现在记的 flash 价和高峰倍数，和官方价格页一致，不用改。

### 5.2 回消息一次多少钱

拿这 7 天回消息的实际 token 数（平均每次约 9600 token 输入，87% 命中缓存，输出约 18 token），按 pro 价重算：

| | flash（账面） | 按 pro 算 |
|---|---|---|
| 7 天回消息合计 | 0.279 元 | ≈ 1.334 元 |
| 平均每次 | 0.0023 元 | ≈ 0.011 元（约 4.8 倍） |

这里贵出来的部分，主要是那 87% 命中缓存的人设：命中缓存的价格 pro 是 flash 的 7.5 倍。

### 5.3 每天会多花多少、1.5 元够不够

假设只换回消息，判断、核对、看图、记忆整理这些还用 flash：

| 情况 | 现在（flash） | 换 pro 以后 | 多花 |
|---|---|---|---|
| 这 7 天平均每天 | 0.073 元 | ≈ 0.22 元 | +0.15 元 |
| 最忙的一天（10/20，74 次回消息） | 0.296 元 | ≈ 1.00 元 | +0.70 元 |
| 9/29 那种量（116 次回消息） | 0.478 元 | ≈ 1.29 元 | +0.81 元，离 1.35 元只差一点 |

每天能聊的轮数大约是这样（一轮回消息，连带它引起的判断、核对、看图和记忆整理）：

| | 每轮大约 | 1.35 元能聊几轮 | 每人份额 0.375 元能聊几轮 | 每群份额 0.75 元能聊几轮 |
|---|---|---|---|---|
| flash | 0.0038 元 | ≈ 350 轮 | ≈ 140 轮 | ≈ 290 轮 |
| pro | 0.0124 元 | ≈ 110 轮 | **≈ 33 轮** | ≈ 67 轮 |

（每人、每群份额只算聊天类，不含记忆整理。）

结论：

- **按现在的聊天量，1.5 元够用**：平均每天 0.22 元，最忙那天约 1.0 元。
- **先卡住的是每人份额**：10/20 聊得最多的那位用户，flash 花了 0.101 元，换 pro 约 0.48 元，超过 0.375 元，聊到一半就会被告别。想换 pro 的话，每人份额要跟着提（比如 0.6～0.75 元），或者接受一个人一天只聊三十来轮。
- **`BUDGET_ROUND_ESTIMATE` 要跟着改**：现在是 0.003，换 pro 后应改成约 0.012。不然“快没钱了，慢慢收尾”的提示会来得太晚。
- **前提：先让记账分模型算价**。现在所有调用都按 flash 价记。换 pro 却不改记账的话，账面只有真实的五分之一左右，限额就形同虚设：账面 1.35 元时，真实大约已经花了 5 元。这是第三批第 2 项（按真实单价记账），**要在换主模型之前做好**。

### 5.4 不确定的地方

1. **pro 回话的长短**：上面假设 pro 和 flash 写得一样长。pro 写得更长的话，输出贵得更多。不过输出只占回消息花费的一小部分（每次约 18 token），影响不大。
2. **缓存命中率**：换模型后，pro 的缓存要重新攒。头几次命中率会低一些，之后应该和 flash 差不多（人设、规则都是固定前缀）。
3. **聊天量**：这 7 天聊得少（平均每天 18 次回消息），而且有测试。人多起来以后，每天的花费主要看回消息次数，按 5.3 的“每轮大约”乘一下就行。
4. **账本只有调用的 token 数，没有时间**：所以算不出高峰时段和空闲时段各占多少。高峰时段两种模型都是两倍价，不影响倍数，只影响总数。
5. **服务器 `.env`**：我看不到。数字按代码默认值和日志算，日志里聊天模型是 `deepseek-flash`、高峰模式关。服务器上改过 `BUDGET_*`、`MEMORY_*_USE_PRO` 的话，请部署 agent 告诉我。

## 6. 建议（改不改由你定）

1. **换主模型之前**：先做第三批第 2 项“按真实单价记账”。限额这边把价格表改成按模型分（flash 一张、pro 一张），记忆 agent 和以后用 pro 的地方记账时带上模型名。
2. **真要换 pro**：每人份额 `BUDGET_USER_SHARE` 提到 0.6～0.75 元，`BUDGET_ROUND_ESTIMATE` 改成约 0.012，总额 1.5 元可以先不动，跑一周看实数。
3. **预留 0.15 元先不动**：等睡前整理按真实价记账以后，再看每晚花多少。
