## 3. 拆的时候怎么保证“行为一点都不变”

1. **只挪不改。** 拆分期间看到想改的逻辑（比如《发前清理清单》第 5 节那几个问题），只记下来，拆完再单独改、单独测。
2. **每挪一步跑一遍全部 329 个程序测试**，全过才挪下一步。数量只能多不能少。
3. **测试里替换函数的地方要跟着改**（大约 50 处，最多的是 `in_peak`、`_in_hours` 各 10 处）。
   - 函数挪走以后，测试要替换新文件里的那个，不然会“假通过”。
   - 为了让替换真的生效，被测试替换的函数，调用的地方一律写成“模块.函数()”，比如 `core.in_peak()`，不写成从模块里单独导入的名字。
   - 这样以后谁加测试都不容易踩坑。
4. **会被重新赋值的状态**（`_quiet_until`、`_same_names` 这类）只放在一个文件里，别处都通过那个文件读写；`conftest.py` 里清状态的那一串跟着改。
5. **旧名字照样能用**：`__init__.py` 把挪走的名字再导出一遍，`qzone_diary.py` 那一长串 `from . import ...` 不用改（空间 agent 的文件我不动）。`phrasing_compare.py`、`replay_chat.py` 这些测试工具照常能用。
6. **测试工具里读提示词的地方**：`regression.py`、`greeting_test.py`、`wrapup_test.py`、`persona_regression.py` 现在都从 `__init__.py` 源码里抠常量。拆完改成先读 `prompts.py`，读不到再读 `__init__.py`，这样拿旧备份当“改前”也照样能跑。
7. **为什么不靠回归测试**：回归测试只从源码里读提示词、直接调 DeepSeek，并不跑机器人的程序，所以它测不出拆坏了没有，只能看提示词变没变。拆分改为用“提示词逐字比对”+ 程序测试来保证，不用花钱跑回归。
8. **测试归属**：测试文件里改的都是“替换哪个模块的函数”这一类，不改断言。`test_voice*.py` 是语音 agent 的，我只改替换的位置，在《版本说明》里写明。
