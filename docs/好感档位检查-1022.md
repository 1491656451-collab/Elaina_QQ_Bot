## 1. 结论

1. **最大的问题是档位几乎用不上**：线上 42 个人里，39 个是陌生人、2 个讨厌、1 个熟人（这个熟人说过 221 次话，卡在男生/没确认性别的上限 129）。普通朋友 0 人，很熟 0 人。影响表里给普通朋友、熟人、很熟分的那些设置（写信、搭话、表情、语音、记几条记忆……）在线上基本没生效。原因是**加分太慢**：模型打分几乎只给 +1，而扣分平均 -2。
2. 陌生人档里攒的分会被回落清零，让问题 1 更严重。
3. 讨厌只出不进：掉进讨厌以后，不管轻重都几乎回不来。线上 2 个讨厌的人都是攒出来的（反复纠缠、性骚扰后又多次纠缠），符合预期；但以后轻度的讨厌也会这样。
4. 另有 3 处档位之间的设置互相矛盾（陌生人的语音、陌生人的搭话、讨厌的人的台词），都不归好感，列给对应的 agent。
5. 检查过没问题的：各功能按档位的数值都是单调的（越熟越多 / 越少），没有哪一档反着来；讨厌的人在语音、写信、搭话、评论说说上都关掉了，前后一致。

## 3. 发现的问题

### 问题 1：档位几乎用不上（加分太慢）

- **现象**：见第 2 节。39/42 是陌生人，普通朋友、很熟一个都没有。
- **后果**：
  - 影响表里大部分按档位分的设置没生效。常来聊的人和第一次来的人，她的态度、表情、语音、搭话几乎一样。
  - 记忆容量也绑在档位上：陌生人每人最多记 8 条、每轮只带 1+2 条。说过 50 多句话的老面孔，她也只记 8 条（归记忆，但根源在这里）。
- **原因**：模型打分保守（几乎只给 +1），档位线又是按"+1～+5"设计的（9/29 设计时算的是每天最多 +12、10 天到很熟）。
- **可选的改法**（选一个或组合）：
  - **A. 降低档位线**（好感改，`config.py` 的 `AFFECTION_FRIEND` / `ACQUAINTANCE` / `CLOSE`）。比如普通朋友 30、熟人 60、很熟 100。按每 5 句涨 1 分算，到普通朋友约 50 句、熟人约 200 句、很熟约 400 句。
  - **B. 让模型敢给高一点的分**（记忆改整理提示里打分那段）：比如明确写"正常聊得愉快就 +2，特别投机、真心关心 +3～+5"。不过 +1 是模型自己的倾向，改提示不一定管用，要用记忆回放测一下。
  - **C. 两个都做**，先做 B，看一周的分数再定 A 要降多少。
- 改档位线会影响所有按档位做事的 agent，按《分工说明》第 3 节，改完要在《版本说明》写清楚，并请你告诉大家。
- **好感 agent 的倾向**：先做 B，再看要不要做 A。现在的数值是按"模型会给 +1～+5"设计的，问题出在模型实际给的分，先从源头看能不能改过来；改不过来再降线。

### 问题 2：陌生人档里攒的分会被回落清零

- **现象**：9/30 定的"回落不改变档位"，陌生人的下限是起步分 20。所以一个陌生人从 20 攒到 35，只要 7 天没来，就会一点点落回 20。线上有 6 个人就是这样：攒到 24～30 分，停了两三周，现在都是 20。
- **后果**：不常来的人永远升不到普通朋友，问题 1 更严重。熟人、很熟停聊也只是落到本档下限（90、130），反而是最需要攒分的陌生人被清零。
- **可选的改法**（好感改 `affection.py` 的 `_tier_bounds`）：
  - **A. 陌生人高于 20 的部分不回落**（只有讨厌、普通朋友以上才按现在的规则）。
  - **B. 陌生人回落更慢**，比如每天 0.5 分。
  - **C. 不改**，当成"太久不来就重新算生人"。

### 问题 3：讨厌只出不进

- **现象**：讨厌的人回落最多回升到 -1（9/30 定的），想变回陌生人只能靠整理时加分，但：
  - 讨厌的人 40% 直接不理，水话 90% 不回，聊得起来的机会本来就少；
  - 加分减半（至少 +1），送面包不加分；
  - 模型给讨厌的人加分本来就难（整理提示写的是"只有特别真诚才给 +1～+2"）。
- **线上的两个例子**：
  - -45.4：反复告白纠缠，攒出来的，符合预期。
  - -7.7：性骚扰 -8 以后又多次纠缠，符合预期。
- 现在没有轻度讨厌的人，但以后有人只是一两次说话难听、掉到 -1～-5，也会一直是讨厌。
- **可选的改法**：
  - **A. 轻度讨厌能淡掉**：比如 -10 以上、没被判过恶意的讨厌回落到 0（变回陌生人），其余的还是只回到 -1。改 `affection.py`。
  - **B. 不改**。

### 问题 4：陌生人会主动收到语音，但被要语音时多半婉拒（归语音 agent）

- **现象**：
  - 抽签发语音：陌生人私聊 6%、群聊 4.5%（`VOICE_TIER_MULTIPLIER` 0.3）。
  - 对方要语音时，给陌生人的提示是"你们还不熟，你多半会客气地婉拒"（`VOICE_REQUEST_TIER_HINT`）。
  - 结果是陌生人没要时她可能主动传声，要了反而多半不给，前后不一致。
- **又因为问题 1**：几乎所有人都是陌生人，这条在线上影响面很大。
- **可选的改法**：陌生人的抽签倍数降到 0（不主动传声），或者婉拒的倾向改轻一点。由语音 agent 定。

### 问题 5：陌生人会被冷场搭话（归聊天 agent）

- **现象**：陌生人冷场搭话概率 8%（`NUDGE_PROB`）。但给陌生人的关系提示是"不热络、不主动关心"；【可以问问】也特意不给陌生人，怕"被盯着"。冷场以后主动凑上去说话，和这两条不太一致。
- 线上两周只搭话了 1 次，正好就是给一个陌生人（对方冷场 1 分钟）。
- **可选的改法**：陌生人的搭话概率改成 0，或者保留但让搭话提示对陌生人更克制。由聊天 agent 定。

### 问题 6：讨厌的人收到的台词、提示偏客气（归聊天 agent，小问题）

- **告别、晚安、"今天累了"**：讨厌和陌生人共用"far"那一套（`peak.py` `TIER_OF`），都是"抱歉，我得走了""有缘再见"这种客气话；但给讨厌的人的关系提示是"明显不耐烦、爱答不理"。
- **倾诉时回短一点**（`turn_hints.py` `length_hint_for`）对讨厌的人也生效，提示文字写的是"你们还不太熟：认真回应"，对讨厌的人说"不太熟"不对。
- 线上讨厌的人只有 3 个，影响很小。
- **可选的改法**：讨厌单独一套更冷淡的台词（或者讨厌的人不道晚安、不告别）；倾诉提示给讨厌的人换一句。由聊天 agent 定。

### 问题 7：几处重复和兜底（小问题，记一下）

- `MEMORY_FACTS_BY_TIER`（`config.py`）和 `FACT_CAP_BY_TIER`（`memory.py`）是同一组数，启动时前者覆盖后者，改的时候容易只改一处。归记忆。
- `core.py` 的 `tier_value()`：表里没写普通朋友时，取陌生人和熟人的中间值。现在所有表都写了普通朋友，这段兜底用不上；以后有人在 `.env` 里只写四档，会悄悄取中间值。不用改，知道就行。
- `LETTER_DAILY_PROB` 老写法兼容里熟人还是 0.08（默认已是 0.12），10/22 已告诉用户，线上不受影响。
