# 识图底片比对测试报告（11/06）

> 识图 agent 写。原始结果：`docs\识图底片比对测试\底片比对_1106_2312.md`（修 bug 前）、`底片比对_1106_2319.md`（修 bug 后、加了 40 张别的表情包）。
> 测的是 11/06 新加的 `selfmatch.py`：别人发来的图如果和她自己表情库 / 说说图库里某张是同一张图，就算她。离线测，不调模型、不花钱。

## 结论

**可以部署。** 她库里的图被压缩、缩小后全都认得出；库里没有的 71 张图一张都没误认。

## 为什么做

本机认人认不出动画截图的近脸特写、便服图（《识图抽查-1022》里漏的 18 张），聊天 agent 的看图对比第 4 项（Y1～Y3）也卡在这里。这些图大多就在她的表情库和说说图库里，用户说过这两个库只放她的图，所以“和库里某张是同一张图”就可以直接算她，不会把别人认成她。

## 结果（修 bug 后，23:19）

### 她的图：处理过以后还认不认得出

图库 162 个文件，算出指纹 158 张。没算的 4 张是超过 1600 万像素的 PNG，服务器上的图库压缩过，不受影响。

| 模拟别人转发 | 认出 |
|---|---|
| 缩小一半、重新压缩 | **158/158** |
| 缩到很小（长边 240）、重压缩 | **158/158** |
| 四边各裁 2% | 157/158 |
| 四边各裁 3% | 151/158 |
| 加 5% 白边 | 157/158 |

QQ 转发表情包、图片，最常见的就是前两种（重新压缩、缩小），全都认得出。认不出的基本都是“四边各裁 3%”，正常转发很少会这样。

### 库里没有的图：会不会误认成她

| 来源 | 张数 | 误认 |
|---|---|---|
| 别的银发角色（识图对照图） | 9 | 0 |
| 复杂图（截图、梗图、漫画） | 6 | 0 |
| 实物照片（伊蕾娜手办，库里没有） | 9 | 0 |
| 聊天截图 | 7 | 0 |
| 别的表情包（用户放的，含 gif、webp） | 40 | 0 |
| **合计** | **71** | **0** |

指纹门槛是 pHash 差 10 位以内。这 71 张离库里最近的一张也差 16 位以上，大多在 20 位左右，余量足够。

### 代价

- 第一次算整个图库：电脑上 10.4 秒，内存峰值约 41 MB。之后存在 `data/self_hashes.json`，只补算新图。
- 每比一张图约 30 毫秒，只在本机认人没认出她的时候才比。

## 测试里修掉的 bug

修 bug 前那次（23:12），说说图 `illust_136837891`（PNG）怎么处理都对不上。查出来是读 JPEG 时为了省内存按灰度解码，颜色缩略图变成了灰的，和彩色的 PNG 对不上。改成按彩色解码、指纹版本号 3 → 4 以后，这张 5 种处理都对上了，误认还是 0。

## 上线后要知道的

- **群友拿她库里的表情包斗图，现在会被认成她。** “认出是自己就搭话”会比以前多一些，还是受 60% 概率、同一个群 10 分钟间隔的限制。觉得太多可以调 `VISION_SELF_REACT_PROB`。
- **只管库里有的图。** 新出的截图、库里没有的同人图，还是只能靠本机认人。想让她认出更多，往表情库或说说图库加她的图就行，10 分钟内会自动补算。
- **库里只能放她的图。** 放进别人的图，那张图就会被当成她。
- 日志里会有“底片比对：和她图库里的 …… 是同一张图”；`/认图` 也会注明。
