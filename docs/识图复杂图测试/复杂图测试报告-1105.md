## 简单的图为什么变长了一点

提示里的“不超过 50 字”改成了“**一般**不超过 50 字”，再加上“复杂的图可以写到 100 字”，看图模型对普通插画也多写了一些背景，比如“背景有浅色光斑”“整体呈冰晶般的折射质感”。平均多 8 个字，最长 72 字，花费和聊天里占的地方都只多一点。现在聊天那边算长短时已经不数图片描述了（见下），所以不影响她回多长。

如果你觉得啰嗦，可以再加一句“单张表情、插画还是 50 字以内”收紧，改完要再测一遍。我的建议是先不改。

## 测试里顺带看到的

- **截图里有人名带方括号（比如 `[鱼香肉丝]`）时，会打乱聊天那边的判断**：聊天 agent 的新代码按 `[图片：……]` 的方括号认出描述、算字数时去掉。描述里自己出现 `]`，会被当成描述到此结束，后半截描述就被当成对方打的字。**已修**：`vision.py` 里把描述中的 `[` `]` 换成 `【` `】`。程序测试 424 个全过，单独核对过：`[图片：一张截图：用户【鱼香肉丝】说“你好”。（画的不是你）]哈哈` 去掉描述后只剩“哈哈”。
- **要聊天 agent 看一下**：去掉“引用的图片”那段时，规则是 `（引用了图片：[^）]*）`，遇到描述里第一个“）”就停了。描述末尾的“（画的不是你）”、描述里的“（一只黑、一只粉）”都会让它提前停下。引用一张图时只多出一个“）”，没关系。**引用两张图时，第二张的描述会整段被当成对方打的字**（我用这次 L2 + N1 的新版描述试过：剩下 60 个字，正好够上“写了一大段”的线），可能又被当成“写了一大段”。建议按括号配对去掉，或者在 `textin.py` 拼引用时给每张描述也套上 `[图片：……]`。出现的条件是引用两张图，概率不高。
- 真实照片（L1 自拍、L6 合影）里的人也被写成“画中人”，末尾加了“（画的不是你）”。这是 10/25 以前就有的写法，意思上没错，先不动。
