# 整理方案：聊天插件拆分（只是方案，还没动代码）

> 2026-09-30 00:50。起因：用户担心改了这么多版以后代码变成“屎山”。目标是**项目好读、不臃肿**：看一个功能只需要打开一个文件；改人设、提示词的人不用碰程序逻辑；以后打补丁有地方放、有据可查。
> 范围：`bot\plugins\roleplay_chat\`，主要是 `__init__.py`。空间（`qzone*.py`）、表情（`stickers.py`）、识图（`vision.py`）已经是独立文件，这次不拆，只理顺它们和主文件的依赖。
> **什么时候做**：上线跑几天、没有急着要改的东西时再做。拆分期间请人设 agent 暂停改 `__init__.py` 里的提示词（人设文件照常可以改）。

**问题不在逻辑乱，而在一个文件装了太多事**：聊天、限额、休息、表情、插话、冒泡、写信、搭话、补未读、加好友、管理员命令全在一起。后果：

- 找一处要翻很久；两个 agent 同时改同一个大文件，容易撞车（今晚就出现过要先核对文件有没有被对方改过）。
- 提示词和逻辑混在一起：人设 agent 想改一句提示，得在 4000 行里找位置；回归测试 `regression.py` 也只能从 `__init__.py` 源码里硬抠这些常量。

- `qzone_diary.py` 反过来从 `__init__` 导入 20 多个名字，所以空间模块必须放在文件最后导入，改的时候要小心顺序。

## 3. 拆的时候要注意的

1. **行为一点都不能变**。每挪一个文件跑一遍 178 个程序测试，全部通过才挪下一个。整件事做完再跑一次 `回归测试.bat`（改前用拆之前的备份），翻车次数应该和拆之前一样。
2. **旧的名字照样能用**：`__init__.py` 里把挪走的名字再导出一遍（`from .prompts import CHAT_RULES` 这种），`qzone_diary.py`、`stickers.py` 这些从 `__init__` 导入的地方不用改；以后再慢慢改成直接从新文件导入。
3. **测试里直接替换函数的要跟着改**：`test_chat.py` 里有 38 处 `monkeypatch.setattr(p, "函数名")`（比如 `in_peak` 9 处、`_in_hours` 9 处、`asleep`、`recall`、`catch_up`……）。函数挪到新文件后，要改成替换新文件里的那个，否则测试会“假通过”。替换 `p.cfg.xxx`、`p.random.xxx` 这种对象属性的 149 处不受影响（对象还是同一个）。
4. **回归测试读提示词的地方要改**：`tools\regression.py` 现在从 `__init__.py` 源码里取 `CHAT_RULES`、`FAMILIARITY_HINT` 这些常量，拆完改成读 `prompts.py`；旧的备份（`__init__.0929x.py.bak`）还要能读，所以两种都支持。
5. **部署**：新增的文件都要传到服务器，一次传齐再重启，别只传一半。

## 4. 做的顺序

从最独立、最不容易出错的开始，每一步单独提交、单独测：

1. `prompts.py`（只挪文字，风险最小，收益最大：以后改提示只看这一个文件）
2. `core.py`、`history.py`
3. `textout.py`、`textin.py`
4. `sleep.py`、`quota.py`
5. `admin.py`、`friends.py`、`online.py`
6. `proactive.py`（顺便合并四种主动说话的共同部分）
7. `recall.py`、`addressed.py`
8. `turn_hints.py`，最后拆 `_converse`

预计每一步半小时到一小时。可以分几天做，做到哪一步都能停，停下来的时候程序是好的。

## 5. 以后怎么防止再变胖

1. **新问题先想能不能靠说清楚解决**：先看人设、提示里是不是没写清、写错了，或者例句被照抄了。今晚“说岔了不认”“关系提示照抄”都是这样解决的，没加词表。
2. **实在要加关键词表、正则，就放进对应的文件，并在旁边写一行注释：哪天、为什么、针对哪次日志**，版本说明里也记一笔。现有的 30 个大多已经有这种注释，拆的时候补齐缺的。
3. **定期清理**：上线观察期过了的兜底表（比如蘑菇词表 `UNPROMPTED_WORDS`）按计划删掉；回归测试里越补越长的判定（N08 那条已经十几种说法），每轮测试后看一下还有没有必要。
4. **一个文件超过 800 行、一个函数超过 150 行，就考虑拆。**
5. **提示词只在 `prompts.py` 里改**，人设只在 `elaina.md` 里改，两个 agent 各改各的文件，不容易撞车。
