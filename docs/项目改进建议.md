## 总评

整体设计很周到：限速、冷却、打字延迟、高峰“很忙”、熔断、宽限期这些该有的都有，耗时的识图、下载也已经放进后台线程。主要问题集中在三类：

1. **“下线后停手”只做了一半**：空间模块会停，聊天、冒泡、写信不会停；空间模块自己也有两条路绕过闸门。
2. **状态只放在内存里**：限额计数、“最近一次空间写操作”、表情刷新时间，重开 `start.bat` 就清零。
3. **长期记忆的整理方式不稳**：档案越长越容易整理失败，失败了会一直卡住；写文件不是原子的，出意外可能清空某人的档案。

## 跨模块的几件事

- **在线状态**：聊1（新建 `presence.py`）和空间模块的空1～空4 要一起改，空间模块改成从 `presence.py` 读在线状态。
- **看图的时机**：识5 和聊10 是同一件事，改在聊天主流程里。
- **人设里的功能说明**：“看到自己的画像”“甩小画像”两节只在识图、表情打开时才拼进去，识图和表情两份里各提了一次。
- **状态落盘**：聊4、空5、表8 可以共用一个存状态的小模块。

## 建议的整体顺序

1. **账号安全**：聊1～聊3 + 空1～空5（统一在线状态、空间闸门补漏、写后被踢自动熔断）
2. **数据**：聊14 原子写 → `.env` 加 `MEMORY_SUMMARY_MAX_TOKENS=4000` → 聊13、聊15；空10～空13
3. **上服务器前**：通1～通6、识1～识4、空16
4. 其余按空闲时间慢慢改

每一批改完都建议重开观察一两天，再改下一批，免得分不清新问题是哪次改动带来的。
