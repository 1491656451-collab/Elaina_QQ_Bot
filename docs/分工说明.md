# 分工说明

> 2026-10-22 重写（替换 9/30 的版本）。现在一共 10 个 agent，各管一块功能。
> - 改某个地方之前，先在这里查它归谁。不归你的，不要直接改：写进对方的交接文档，或者告诉用户，由用户转达。**agent 之间不直接联系，由用户协调**（9/30 定）。
> - 第 2 节的文件位置是 **10/22 代码拆分之后**的样子（聊天 agent 10/22 改）。插件目录是 `bot\plugins\roleplay_chat\`，下面只写文件名。
> - 拆分后 `__init__.py` 只剩导入、再导出、启动和关机时开关后台任务；它开头的说明里有一份“文件分布”，和这里一致。共用的 `core.py`（配置、模型客户端、记账、长期记忆对象、查档位、“她只有一双手”、出错通知）由聊天 agent 维护，别人要改先说。

## 1. 一览

| agent | 一句话 |
|---|---|
| 聊天 | 她怎么说话：规则、提示词、回消息主流程、发出去之前的清理、主动说话（插话、冒泡、搭话、写信）的流程和文字 |
| 人设 | 她是谁：`elaina.md` |
| 记忆 | 她记住什么：长期记忆的整理、核对、使用 |
| 好感 | 她对每个人多熟：好感分、档位、加减分、性别上限 |
| 限额 | 她能花多少钱、什么时候休息 |
| 语音 | 她怎么发声：语音服务、发语音的时机 |
| 表情 | 她怎么甩表情 |
| 识图 | 她怎么看图 |
| 空间 | QQ 空间：说说、评论、空间风控 |
| 部署 | 服务器、部署、运维、账号风控 |

## 2. 各 agent 管的东西

### 2.1 聊天 agent

| 管什么 | 文件和位置 |
|---|---|
| 聊天规则、回忆规则、关系提示的写法、长短提示、迟回 / 收尾 / 休息提示的文字，以及插话 / 冒泡 / 写信 / 搭话、【传声】等所有给模型的文字 | `prompts.py`（只有文字，没有逻辑） |
| 回消息主流程：合并、拼提示、调模型、检查、发送 | `reply.py`（`_converse`） |
| 要不要回：触发规则、判断是不是在跟她说话、消息计数、她说要走了以后一阵子不回 | `addressed.py` |
| 聊天记录、收到的消息怎么变成文字、每轮提示（时间感、长短、送礼提示） | `history.py`、`textin.py`、`turn_hints.py` |
| 防幻觉、发出去之前的清理 | `textout.py`（`clean_reply`、截断、去括号等）、`story.py`（查小说资料、核对往事）、`factcheck.py`、`echocheck.py`、`oocheck.py`、`knowledge.py` |
| 主动说话：插话、冒泡、冷场搭话、写信的流程 | `proactive_group.py`（群里旁听、插话、冒泡）、`proactive_private.py`（写信、搭话）；`INTERJECT_*`、`BUBBLE_*`、`NUDGE_*`、`LETTER_*` 参数（按档位的概率数值见第 3 节） |
| 所有要说出口的固定台词（晚安、告别、累了） | `peak.py` 的台词表 |
| 别的功能加进每轮提示里的文字（【传声】提示、送礼提示等） | 文字归聊天，什么时候加归对应功能（见第 3 节） |
| 补回未读私聊（含上线 / 断线时开关后台任务）、加好友验证消息、`/重置`、`/重载人设`、`/插话`、`/冒泡`、`/搭话`、`/写信` | `catchup.py`、`friends.py`、`commands.py`、两个 `proactive_*.py` |
| 回归测试、对话回放、措辞对比等聊天相关的测试工具 | `tools\regression.py`、`regression_cases.json`、`replay_chat.py`、`phrasing_compare.py` 等 |

### 2.2 人设 agent

| 管什么 | 文件和位置 |
|---|---|
| 人物设定 | `bot\personas\elaina.md`（改前备份放 `docs\人设打磨备份\`） |

### 2.3 记忆 agent

| 管什么 | 文件和位置 |
|---|---|
| 长期记忆：什么时候整理、整理提示、档案格式、遗忘、整理后核对、睡前整理、给她看的【长期记忆】和【可以问问】 | `memory.py`（好感部分在 `affection.py`，见 2.4）；`config.py` 里 `memory_*`；`memory_chat.py` 里的定时补做 `_memory_retry_loop` |
| `/记忆`、`/忘记`、`/改记忆` | `memory_chat.py` |
| 记忆的测试工具 | `tools\memory_replay.py`、`memory_regression.py`、`memory_model_compare.py` |

整理时模型会给出好感变化和性别判断，**怎么给（整理提示里的这部分写法）归记忆，给出来以后怎么算分归好感**。

### 2.4 好感 agent

| 管什么 | 文件和位置 |
|---|---|
| 好感分的存取、范围、档位分数线、每天加分上限、纠缠扣分上限、回落 | `affection.py`（`AffectionMixin`，`LongTermMemory` 继承它）；`config.py` 里 `affection_*`。整理完按对话加减分那段暂时还在 `memory.py` 的 `_summarize` 里，改它先问用户 |

## 4. 大家都要遵守的

1. **写回任何文件前先重新读一遍**，看修改时间有没有变；变了就把别人的改动合进来，不要直接覆盖。
2. **每次改动在《版本说明与管理员指令.md》记一行**：只往当天那一节的末尾**追加**，不要拿旧底稿整份重写（10/19、10/20 两次被盖掉过）。docs 里和项目里都要同步。
3. 改完不管部署，在那一行末尾标"还没部署"；部署 agent 部署完改成"已部署"。
4. 改了默认值，顺手改《版本说明》第 1.3 节功能一览和第 4 节参数表里对应的那一行。
5. **代码拆分已在 10/22 完成**（见《版本说明》10/22“拆分完成”那一行）。拆分后：各改各的文件；**测试要替换的函数，调用的地方一律写成“文件.函数()”**（比如 `core.in_peak()`、`sleep.asleep()`），测试也替换那个文件里的（`monkeypatch.setattr(p.core, "in_peak", …)`），不然测试会“假通过”；会被整个换掉的状态（比如 `_quiet_until`）只放在一个文件里。
6. 含真实 QQ 号、群号、聊天原话的文档和测试数据不上 GitHub，新建这类文件时告诉部署 agent 加进 `.gitignore`。
