> 2026-10-22 整理（同日更新：你确认版本说明里的改动已全部部署；人设已补"传声说家乡话"）。依据：项目里的《版本说明与管理员指令》（截至 10/21 02:05）、《分工说明》《风控记录》《怪话清单-1018》《措辞对比报告》三轮、《文件整理清单-1021》等。

## 1. 总体评价

对一个自用、小群用的机器人来说，完成度很高：人设贴近原作，拟人节奏细致，风控和花钱都有兜底，每处改动都能追溯。

现在的主要问题不是功能少，而是**复杂度涨得比效果快**：

- 提示词越叠越多，程序兜底也越来越多。旧问题修好了，叠加出来的新怪话又冒出来。
- 不少别扭的话是 flash 模型本身的水平（措辞对比三轮的结论），再往提示里加规则，收益越来越小。
- 十个 agent 同时改少数几个大文件（`__init__.py`、`memory.py`），协作成本已经开始出事故。

## 3. 各 agent

### 3.1 聊天 agent

**管什么**：聊天规则和各种提示、回消息主流程、防幻觉、发出去之前的清理、回归测试。

**做得好的**
- 测试工具链最完整：回归测试、对话回放、措辞对比盲评、停止符实验。改前改后对比，被判翻车的原话逐条审。
- 敢用数据推翻直觉：比如"说人话"这条规则第二轮测出来反而略差，就没加。
- 线上问题修得快：10/20 13:04 发语音整条丢失，13:09 修好，13:42 上线。

**问题**
- **程序兜底越来越多**：出戏检查、蘑菇退回、乱码截断、替对方说话截断、半截字、动作括号、整句括号去掉、`[name=…]` 伪标签……每一条单看都合理，合在一起，规则之间会互相影响（`[name=…]` 那次就是"没人提过的外文"检查把整条截没了）。
- **怪话的大头是模型水平**：措辞对比三轮，各种写法的差距都在波动范围内，每 15～20 句冒一句别扭的话。
- 主流程 `_converse` 在 `__init__.py` 里，限额、语音、记忆的调用都穿插在里面。

**建议**
1. 把发出去之前的清理整合成一处，列一张表：每条清理是什么、为什么加、哪天加的，能删的删掉。
2. 认真试一次聊天主模型换 pro。按 9/29 的实账，回消息一天约 0.22 元，pro 约 4 倍价格，**粗算**可能还在 1.5 元以内，但要按现在的用量重新核算（和限额 agent 一起）。用《怪话清单》里的真实场景做盲评。
3. 和人设 agent 一起做提示词审计（见 2.7）。

### 3.2 人设 agent

**管什么**：`personas\elaina.md`。

**做得好的**
- 用原作台词对照着改，口头禅分清"嘴上说的"和"只写在心里的"。
- 最早发现"给例句会被照抄"，把示例都改成只写态度、给几种说法，效果有数据：很熟的人告白照抄从 10/10 降到 0/10。
- 每次改动都留备份、做重点复测。

**问题**
- **人设越写越长**：从 8757 字涨到 11339 字，每轮都带。补的大多是"别这样、每次换说法"一类的限制，措辞报告推测，这些限制叠在一起可能正是让她"硬凹俏皮话"的原因之一（**还没验证**）。
- **面包是老问题**：人设、记忆、聊天三边都修过，回归测试里还时不时冒出来，最后改成"只数不判"。
- 日语语音这件事 10/21 已经补好（传声说的是"家乡的话"，意思会一起传到；见《人设复测报告-传声家乡话》），被问到时 30/30 都答得上来。剩下的小毛病是偶尔照着聊天记录写出「[传声]」标记，线上由程序去掉。

**建议**
- 做一次"减肥"：合并重复的限制，删掉已经由程序兜底的说明，看看短的版本回归会不会变差。

### 3.3 记忆 agent

**管什么**：长期记忆的整理、档案格式、整理后核对、睡前整理、【可以问问】。

**做得好的**
- 成本控制最好：整理从每次 0.0061 元降到 0.0013 元（改成只写增删改、固定规则放最前面命中缓存）。
- 核对改问法（只问"这是谁的事"）后，错的挡下 25/25，对的误挡 0/25。
- 私聊知道的事不带到群里和空间，几轮回放都是 0 次。

**问题**
- **整个项目里最复杂的一块**：类型、重要度、按关系遗忘、关键词、性别证据链、★提醒、整理后核对、睡前用 pro 整理……线上不少怪话是从记忆来的：面包越滚越大、枕头记反、"伊蕾娜提醒过他生日"主语反、过时的近况被当成现在。
- **睡前整理的钱算少了**：用的是 pro，但按 flash 单价记账（10/16 18:40 那条自己写了"实际更贵"），所以 `/花费` 里这一项偏低，限额判断也会偏松。

**建议**
1. 睡前整理按 pro 的真实单价记账（和限额 agent 一起改）。
2. 暂停加新机制，观察一两周线上：看《怪话清单》里归记忆的几条还会不会出现。

### 3.4 好感 agent

**管什么**：好感分、档位、加分扣分规则、回落、性别上限。

**做得好的**
- 规则的原则清楚，而且是你定的：卖惨算纠缠照扣、单纯倾诉不扣；玩笑和恶意分开；扣分不设总上限，只有容易重复的事设上限；回落不掉档；每天最多 +10。
- 9/29 那次"倾诉被扣到 -28"之后，规则补得很快。

**问题**
- **代码在 `memory.py` 里**，和记忆 agent 共用一个文件；《分工说明》里好感还归记忆。现在拆成两个 agent，交界不清最容易出冲突。
- **档位的影响散落在各处**：带表情、发语音、冷场搭话、水话不回、写信、评论好友说说、身材梗扣分，都各自有一套按档位的倍数或概率，分别在不同参数里。改一个档位的分数线，影响到哪些地方，没有一张表能一眼看清。
- 性别上限让男生和没确认的人最高到熟人，这是你定的设计，没问题；只是要知道，"很熟"那一档的各种概率实际上只对极少数人起作用。

**建议**
1. 把好感从 `memory.py` 分出去，单独一个文件。
2. 出一张"各档位影响表"：每个档位在每个功能里的概率、倍数，放进《好感度机制说明》。

### 3.5 限额 agent

**管什么**：记账、每天上限、按人按群分账、收尾和告别的时机、晚上休息。

**做得好的**
- 按钱限额替代按条数限额，按 DeepSeek 返回的实际用量记账，重启不清零。
- 聊天停下时一定给记忆整理留钱；话没说完先收尾再告别；两轮之间花完也会补告别。

**问题**
- **开销项变多了，预算没重新算**：9/30 定 1.5 元以后，又加了整理后核对、睡前 pro 整理、讲往事核对、每轮约 100 字的传声提示、语音翻成日语的调用；10/20 又取消了"高峰很忙"，工作日白天每句话按 2 倍价算。预留的 0.15 元还够不够、每天几点花完，文档里没看到新的核算。
- 睡前整理记账偏低（见 3.3）。

**建议**
1. 拿最近一周的 `data/usage/*.json` 重新核算：每天总花费、几点花完、各项占比。
2. 根据结果决定上限要不要调、预留要不要加。

### 3.6 部署 agent

**管什么**：服务器、部署、运维、风控登录问题。

**做得好的**
- 部署前在和服务器一样的环境（Linux、Python 3.12）跑全部程序测试，还拿服务器的真实档案离线读一遍。
- 推送前检查 `.gitignore`，含 QQ 号、群号的文档都挡在 GitHub 外面。
- 风控记录写得清楚，每次都分清"发生了什么、之前在做什么、判断、对策"。

**问题**
- 部署完没回头改文档里的"还没部署"标注（见 2.4）。
- **人设不走 git**，靠 scp 单独传，服务器上是哪一版只能靠记录的字数对。
- **账号层面的风险还在**：风控记录 9 次里，后几次都和机器人的行为无关，更像腾讯定期作废这个号的登录（#8、#9）。这不是代码能解决的，长期看是整个项目最大的不确定性。

**建议**
1. 把版本说明里过时的"还没部署"标注改掉；以后部署完同步改标注。
2. 人设也纳入版本管理（比如一个私有仓库，或者至少每次部署记下文件的校验值）。
3. 风控记录里继续记每次登录撑了多久，看趋势。

### 3.7 语音 agent

**管什么**：电脑上的语音服务（GPT-SoVITS）、训练和样音、机器人里发语音的逻辑。

**做得好的**
- 素材筛选严格（两轮抽查），样音对比 9 轮，每轮都让你盲听再定。
- 及时止损：中文怎么调都念不准，RVC 又不像，就改成日语语音加中文文字，没有继续耗下去。
- 细节到位：一键开关、短句被吞换种子重念、名台词用原句当参考音频。

**问题**
- **依赖你电脑开着**：打游戏、关机时就没有语音，她什么时候能"传声"是不稳定的。这本身没问题（连不上就只发文字），只是用户那边感受到的是"有时候有、有时候没有"。
- **日语语音会不会出戏**：人设已经能接住"你怎么说日语"（见 3.2），但群友实际听到的感受还没有线上反馈。
- 每条语音多一次翻译调用，算进花费（见 3.5）。
- 训练留下的文件占很多盘，《文件整理清单-1021》已经列了可以删的。

**建议**
1. 10/21 那批已经上线，看线上一周：发了多少条、对方有没有接话、有没有人说听不懂。
2. 清理文件（按整理清单）。

### 3.8 表情 agent

**管什么**：收藏表情的拉取、情绪标签、什么时候发、发哪种。

**做得好的**
- 按关系调整概率和能用的情绪（讨厌的人只收到嫌弃、无语、敷衍）。
- 9/27 按改进建议修了下载失败误标、拉满上限、打标签前缩图等问题；文字发出去、表情没发出去时不再留"发了表情"的记录。

**问题**
- 9/27 以后文档里基本没有新记录，**也没看到线上效果的统计**：一天发了多少、发得合不合时宜、有没有发错情绪。
- 情绪固定 10 个，写死在代码里。

**建议**
- 做一次线上抽查：从日志里挑几十次发表情的场景，看合不合时宜，有问题再改。

### 3.9 识图 agent

**管什么**：本机认人（WD14 Tagger）、看图描述、识图缓存。

**做得好的**
- 本机认人不花钱；int8 量化把模型从 446 MB 压到 167 MB，解决了服务器内存问题。
- 大图先缩再看、超大图跳过、内存池关掉，服务器上没再因为识图卡死。
- 区分"画的是她 / 画的不是你"，修好了把别人的画当成自己。

**问题**
- **服务器只有 2G 内存**，识图曾经两次让服务器卡死，这块始终是内存最紧的地方。
- 10/20 取消"高峰很忙"以后，工作日白天也看图、也按 2 倍价算。
- 9/29 以后没看到新的误认率测试。

**建议**
- 定期看一下服务器内存峰值；抽查最近的认图结果，看门槛 0.72 还合不合适。

### 3.10 空间 agent

**管什么**：每天的说说、回评论和 @、评论好友说说、空间风控。

**做得好的**
- 风控做得最细：启动后冷静期、刚要到凭证不写、下线立刻停、一出风控信号熔断 24 小时、节奏打散。
- 楼中回复总报 -10049，对照所有记录推出是 `commentUin` 填错了。

**问题**
- **-10049 的修复还没看到验证结果**：9/29 写的是"要等下次真的回一条才能确认"，之后文档里没有结论。
- 空间是风控最敏感的部分（风控记录 #2～#4 都和空间写操作有关），9/29 又把每天回评论调到 30 条、评论好友说说调到 5 条。
- 9/29 以后没有新的文档，空间这块现在稳不稳，只能从风控记录间接看出（10/07 那次和空间无关）。

**建议**

## 4. 建议的先后顺序

| 顺序 | 做什么 | 谁 |
|---|---|---|
| 1 | 重写《分工说明》，按十个 agent 写清边界 | 你定，任一 agent 起草 |
| 2 | 把版本说明里过时的"还没部署"标注改成"已部署"，顺带更新 1.3 功能一览 | 部署 agent |
| 3 | 代码拆分，至少把语音、好感、限额分出去 | 拆分（或指定一个 agent） |
| 4 | 重新核算每天花费，睡前整理按真实单价记账 | 限额 agent + 记忆 agent |
| 5 | 提示词审计 + 人设减肥 | 聊天 agent + 人设 agent |

| 7 | 表情、识图、空间各做一次线上抽查 | 各自 agent |

前四项是"减法"和"对账"，不加新功能，建议先做完再继续加东西。
