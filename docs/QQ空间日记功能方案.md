## 0. 需求（已确认）

| 项 | 决定 |
|---|---|
| 发布 | 每天自动发 1 条说说：1 张伊蕾娜的图 + 根据图写的文案，可长可短 |
| 图片来源 | 图库轮换，你准备图。以后可以写脚本从网上找候选图，由你人工挑选 |
| 文案素材 | 当天的聊天。白名单群全算；私聊只算**有长期档案**（聊过、有印象）的人 |
| 聊天对象的称呼 | 一律是她"**新认识的人**"或熟人，不叫"旅人"。很熟的人可以被"认出来"，也可以只写"老熟人" |
| 好感度的影响 | 决定哪些事会被写进去、怎么写（见 4.2） |
| 审核 | 不审核，全自动 |
| 可见范围 | 所有人可见 |
| 自己说说下的评论 | 按聊天规则回复。只回直接对她说的，别人之间聊天不插嘴 |
| 别人空间里的 @ | 别人在说说里 @ 她、在评论里 @ 她或回她，也按聊天规则回。只回 24 小时内的；每处只回一次；和自己说说下的评论共用每天的回复上限（现在 10 条）。下线之后你决定保持打开 |
| 风控保护 | 空间一出现风控信号就自动停 24 小时并私信你；凭证用到失效才重取；查评论 2 小时一次 |

## 1. 整体流程

```
白天：群聊 / 私聊 / 空间评论 ──► 长期记忆整理（每 8 条一次）
                                   └─ 顺便产出"今日见闻" ──► data\qzone\daily\日期.json

20:00  日结：今天有新消息、但还没攒够 8 条的会话，提前整理一次
20:30～22:30 随机一个时刻（每天早上定好，重启不会变）：
   ① 按好感度挑 0～3 件见闻
   ② 按见闻的关键词和当前季节去图库挑图（60 天内不重复）
   ③ 写文案（一次模型调用）→ 出戏检查、隐私检查，有问题就重写一次，还有问题就删掉那几句
   ④ 从 NapCat 拿 cookie → 上传图片 → 发说说（所有人可见）
   ⑤ 记进 posts.json。之后有人在聊天里提到她的说说，她知道自己写过什么
   发布失败会隔 10 分钟再试，最多 3 次；3 次都失败就私信管理员

9:00～次日 1:00，每 2 小时（随机浮动 ±15%）查一轮：
   ① 自己最近 7 天的说说下的评论 → 对她说的，按聊天规则回
   ② "与我相关" → 找出别人说说里在对她说的话 → 按聊天规则回（第 8 节）

任何时候空间一出现风控信号 → 熔断：空间功能全部停 24 小时，私信管理员（第 9 节）
```

## 3. QQ 空间接口

### 3.1 登录

调用 NapCat 的 `get_cookies`（`user.qzone.qq.com`），拿到 `uin`、`skey`、`p_skey`，再用 `p_skey` 算出 `g_tk`。凭证**一直复用**，只有接口提示登录失效时，才重新要一次再试。以前每 30 分钟要一次，等于 QQ 客户端每半小时就去服务器要一次授权，频率不自然，下线后改掉了。

### 3.2 用到的接口

这些都是网页版自己用的接口，参考了社区开源插件的实测结论：

| 用途 | 接口 | 实测 |
|---|---|---|
| 上传图片 | `cgi_upload_image` | ✅ |
| 发说说 | `emotion_cgi_publish_v6`（`ugc_right=1` 所有人可见，测试时用 64 仅自己可见） | ✅ |
| 删说说 | `emotion_cgi_delete_v6` | ✅（见 3.3） |
| 读自己的说说列表 | `emotion_cgi_msglist_v6` | ✅ |
| 读说说详情（自己的或别人的） | `emotion_cgi_msgdetail_v6` | ✅ |
| 发评论、回复评论 | `emotion_cgi_re_feeds` | ✅（自己的和别人的说说都试过） |
| 与我相关 | `feeds3_html_more`（`scope=1`） | ✅ 能读到，也能认出 @ |

### 3.3 踩过的坑

- **回复接口成功时也只回一段网页**：发完要回查评论详情，找到自己刚发的内容才算成功。
- **删说说接口也回网页**：结果 `"code":0` 包在网页里的 `frameElement.callback({...})` 中。第一版没认出来，明明删掉了却报"失败"，现在已经改成先从网页里把结果挖出来。
- **空间没有"楼中楼里再套楼"**：回复楼里任何一条，`commentId` 都填这一楼顶层评论的 id，再在正文前加 `@{uin:…,nick:…,who:1,auto:1}` 标明在回谁。
- **`-10049 使用人数过多，请稍后再试`**：不是真的人多，是空间在限制这个号。19:24 出现，13 分钟后设备被下线。现在一出现就熔断（第 9 节）。
- **"与我相关"里的 @ 不是标记，是链接**：数据是网页片段，@ 显示成指向她空间的"@Elaina"链接。所以只用它来定位（哪条说说、什么动作），谁说了什么再用说说详情接口（JSON，带 @ 标记）去读。

### 3.4 风险

- 这些不是公开接口，腾讯改了就会失效。失效时私信管理员，同一类问题 1 小时只提醒一次，不影响聊天功能。
- **会连累设备**：空间接口用的是 NapCat 那台设备的登录凭证，空间里的异常会被记到这台设备头上。9 月 26 日那次下线就是这样。

## 4. 今日见闻

### 4.1 怎么来的

长期记忆整理时，模型顺便挑出 0～2 件"她会想写进日记的事"：

```json
{"qq": 123456, "event": "和我争论哪家面包最好吃", "mood": "得意", "keywords": ["面包", "下雨"]}
```

- 只写话题层面，不超过 25 字，不写名字和私事细节。
- 这个人必须出现在这段聊天里。
- 私聊来的见闻，对方必须有长期档案，也就是有"印象"。
- 空间里的对话（评论、@）也会产生见闻。

### 4.2 按好感度挑选和写法

每条说说写 0～3 件，概率分别是 10% / 55% / 25% / 10%。同一个人一天只写一件。

| 档位 | 被选中的权重 | 写法 |
|---|---|---|
| 很熟 | 5 | 分量重，嘴硬但在意。**可以用对方的称呼让本人认出来**，也可以写"某个老熟人" |
| 熟人 | 3 | 随口一提带点调侃："一个熟人""之前认识的某人" |
| 陌生人 | 1 | 一笔带过："**新认识的人**" |
| 讨厌 | 0.6，而且每条说说只有 20% 的概率允许写 | 只拿来吐槽："那个烦人的家伙" |

- 当天没有见闻：写旅途中随手编的一件小事，或者只写图里的场景和心情。
- **隐私检查**：文案里出现今天见闻里任何非"很熟"的人的昵称，或者出现 5 位以上的数字，就重写；重写后还有，就删掉那几句。

## 5. 图库

- **自动处理**：放进 `bot\qzone\images\` 的图，会在启动约 90 秒后，以及每次发说说前自动处理：
  1. 压缩：原图不动，压缩结果另存到 `cache\`。测试用的 20 张图压缩后在 150～800KB 之间。
  2. 认人：用本机的角色识别确认是不是伊蕾娜。没认出的图不会被排除，只是挑图时排在后面。
  3. 看图：deepseek-flash 写一段 60 字以内的描述，加 3～6 个标签（场景、动作、情绪、物品），以及季节、时段、天气。每张图只看一次。
- **现状**：20 张全部处理完，19 张认出是伊蕾娜；没认出的是那张穿红毛衣、双手合拢在嘴前的。
- **挑图**：
  - 和见闻关键词匹配 +2，季节相符 +1，季节不符 -1，没认出伊蕾娜 -1.5，再加一点随机，然后从前 3 名里随机挑一张。
  - 60 天内用过的不再用；实在不够时，从最久没用的四分之一里挑。
- **不想用某张图**：删掉文件，或者在 `gallery.json` 里给它加 `"disabled": true`。
- **补图**：20 张图按 60 天不重复，大约 20 天后开始重复用，建议慢慢补到 60 张以上。

## 6. 写文案

- **一次模型调用**，提示词包括：
  - 人设
  - 日期、星期、时段
  - 配图描述
  - 挑出的见闻，每条附上对应档位的写法
  - 最近 5 条说说（防重复）
  - 篇幅
- **篇幅**（每天随机）：
  - 35%：一句话（10～25 字）
  - 45%：两三句（30～70 字）
  - 20%：小游记（100～200 字）
- **规则**：
  - 不落款，结尾的"——伊蕾娜"会被自动去掉。
  - 不加话题标签，最多一个颜文字。
  - 不出现"日记""说说""配图"这些字眼。
  - 不把聊天对象叫作"旅人"。
- **费用**：每天约 3000 输入 token + 几百输出 token，一个月不到 1 毛钱。

## 7. 自己说说下的评论

### 7.1 回不回

| 情况 | 回不回 |
|---|---|
| 一级评论，没 @ 别人（包括 @ 了她） | ✅ |
| 楼里 @ 了她 | ✅ |
| 楼主在自己那一楼接着说，而且她之前在这楼回过 | ✅ |
| 一级评论 @ 了别人 | ❌ |
| 楼里别人之间聊（@ 了别人，或者没 @ 地回楼主） | ❌ 不插嘴 |
| 超过 24 小时的旧评论 | ❌ 不补回 |
| 同一个人在同一楼已经来回 3 轮 | ❌ |

### 7.2 怎么回

- 按评论人的好感档位和个人档案回复，档案和聊天共用；没档案就当陌生人。
- 长短随机、出戏检查、雷点扣分、讨厌的人 40% 不理，都和聊天一样。
- **同一个人在同一条说说下连着说了好几句**：合成一次，回最新那条，前面几句一起给她看。
- 模型能看到的内容：这条说说的文案和配图、这一楼到目前为止的对话、和这个人之前在空间里的对话（最近 6 条）。
- 回复合成一行发出，不分条。回楼里某个人时会带上空间的 @ 标记，对方会收到提醒。
- 回复计入全局每分钟、每小时的回复限额和个人冷却。刚回过同一个人时，先等冷却时间过去再回，不拖到下一轮。连着回几条时，每条之间隔 20～90 秒。
- 每天最多回 10 条（自己说说下的评论 + 别人空间里的 @ 合计）。

## 8. 别人空间里的 @（新增）

### 8.1 为什么只能定时读

实测过：有人在说说、评论里 @ 她时，NapCat 和机器人窗口都没有收到任何事件，只有"对方正在输入"之类的。也就是说 NapCat 不转发空间提醒，只能定时去读"与我相关"，也就是空间里那个小红点点开后的列表。

### 8.2 流程

每轮查完自己说说下的评论后：

1. 读一次"与我相关"，只挑别人说说上的动态：提到我、评论提到我、回复、评论……点赞之类的不管。她自己说说上的动态已经由第 7 节处理，这里跳过。
2. 超过 24 小时的、已经看过的动态跳过。动态有新动静时，它的时间会变，会被当成新的动态重新看。
3. 对每条有新动静的说说，读一次详情（JSON），按下表找出在对她说的话：

| 情况 | 回不回 | 怎么回 |
|---|---|---|
| 说说正文 @ 了她 | ✅（她还没在这条说说下评论过才回） | 在这条说说下评论一句；有配图的话先用识图看一眼 |
| 一级评论 @ 了她 | ✅ | 回复这条评论 |
| 楼里 @ 了她 | ✅ | 回复这一条 |
| 她开的那一楼里，有人没 @ 任何人地接话 | ✅（在回她） | 回复这一条 |
| 一级评论没 @ 她 | ❌（在跟楼主说） | |
| 楼里别人之间聊 | ❌ 不插嘴 | 例如一条说说下，另一位好友提问、楼主回答，她不会插嘴 |

4. 同一个人在同一条说说下连着 @ 了好几句：合成一次，回最新那条。
5. 每处只回一次，同一楼最多来回 3 轮，和第 7 节共用每天的回复上限（10 条）。
6. 保底：详情里万一没带 @ 标记，就以"与我相关"里的动作（"提到我""评论提到我"）为准，补上该回的那一处。

### 8.3 回复时她知道什么

- 说说主人的称呼、说说原文、配图的描述、这一楼到目前为止的对话。
- 这个人的好感档位和长期印象。空间里的对话也会记进这个人的记忆。
- 别人的说说里可能直接写着"聊天机器人""设定是《魔女之旅》"。她会像聊天时一样当成听不懂的话岔开，出戏检查照常生效。

### 8.4 用真实数据核对过（只读）

| 说说 | 结果 |
|---|---|
| 一条测试说说下，同一个人连着 3 条 @ 她的评论 | 3 处都认出来了，合成一次，回最新那条 |
| 别人说说正文里 @ 了她 | 认出正文 @ 了她 → 去评论一句 |
| 同一条说说下，另外两个人之间的对话 | 不插嘴 |
| 一条没有权限看详情的说说 | 跳过，不再重复读 |

## 9. 风控保护（2026-09-26 下线后加的）

### 9.1 熔断

- **触发条件**，任意一个接口出现以下情况：
  - 限流码 `-10049`，或者提示"使用人数过多""操作过于频繁""请稍后再试"；
  - 验证或风控页面；
  - HTTP 403。
- **触发后**：
  - 这一轮剩下的操作立刻停。
  - 空间功能全部停 24 小时（发说说、回评论、回 @；聊天不受影响）。
  - 私信管理员：原因、停到几点、怎么提前恢复。
  - 记一行到 `data\risk_events.log`。
- **熔断期间**：`/说说 立即发`、`发预览`、`删除最新`、`查评论` 都会被拦住并提示；`/说说 今日` 会显示熔断状态。
- **解除**：到点自动恢复；想提前恢复就发 `/说说 恢复`。
- **时长**：`QZONE_RISK_PAUSE_HOURS` 控制，默认 24。

### 9.2 降频

| 项 | 以前 | 现在 |
|---|---|---|
| 查评论和 @ | 每 30 分钟 | 每 2 小时 |
| 每天最多回复 | 30 条 | 10 条 |
| 向 NapCat 要空间凭证 | 每 30 分钟 | 失效了才要 |
| 每轮最多回几条 | 不限 | 2 条，剩下的留到下一轮 |
| 同一轮两条回复之间 | 20～90 秒 | 2～5 分钟 |

另外，回复发出后回查没找到，就**不记进记忆、也不算回过**，免得她以为自己说过。这条也不再重试：万一其实发出去了，重试会重复。

### 9.3 风控事件记录

`bot\data\risk_events.log` 会自动记下：

- 机器人连上、断开 NapCat。断开那行附带"最近一小时回复了几条""最近一次空间写操作是多久以前、做了什么""空间功能开没开"。
- NapCat 报告账号下线（如果 NapCat 会推这个事件的话）。
- 空间风控信号、熔断、手动解除。

出事后先看这个文件，再把结论写进 `D:\QQBot\docs\风控记录.md`。

## 12. 测试

### 12.1 模拟测试（假空间、假 DeepSeek、假 NapCat）

- **图库、日结、写文案、定时发布**：通过。大图压缩、透明底垫白、落款去掉、出戏和泄露昵称都能重写。
- **自己说说下的评论**：通过。一级评论会回；@ 别人的、超过 24 小时的不回；楼主接着说会回，第三人插话不回；不会重复回。
- **别人空间里的 @**：用真实的"与我相关"数据跑过，通过：
  - 正文 @ 她：去评论一句。
  - 同一个人连着 3 条 @：合成一次，回最新那条。
  - 别人之间聊天的那一楼：不插嘴。
  - 没权限看的说说：跳过。
  - 再查一次不会重复；对方在楼里接着 @ 她，会带 @ 标记回复。
- 模拟中还发现并修掉了两个问题：
  - 被限流推迟的 @，下一轮会漏掉。
  - 同一个人连着 @ 会一条条分开回。
- **聊天回归**：通过。私聊正常回复，提到"说说"时会带上最近一条说说，`/说说` 各指令正常。

### 12.2 熔断测试（模拟）

- 模拟回复时空间返回 `-10049`：这一轮立刻停下，熔断 24 小时，私信管理员一次。
- 熔断期间，定时任务不动；`/说说 查评论` 被拦住；`/说说 今日` 显示熔断状态。
- `/说说 恢复` 能解除熔断。
- 把每轮上限设成 1 条模拟：第一轮只回 1 处，剩下那处在下一轮补回，没有漏掉。
- 断线和下线事件都写进了 `risk_events.log`，附带"最近一次空间写操作"。

### 12.3 接下来

1. 空间功能保持打开（你的决定）。头几天每天看一眼 `risk_events.log`，对照《风控记录.md》。
2. 现在的默认值已经比较保守：2 小时查一次，每天最多回 10 条，回复 @ 保持打开。
3. 打开后如果又熔断，第一个考虑关的是回复 @（`QZONE_MENTION_REPLY=false`）。
