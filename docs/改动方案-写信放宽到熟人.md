# 改动方案：写信放宽到熟人

状态：**9/30 已实施**（①～⑤ 代码、⑥ 文字说明都已改完；另外把 `LETTER_DAILY_PROB` 的五个档位都写明了，免得 `tier_value()` 对 friend 自动取中间值）
依据：9/30 读到的 `__init__.py`、`config.py`；`.env` 里没有 `LETTER_*` 相关的设置。

## 背景

写信现在只寄给"很熟"的人。男生和没确认性别的人好感最高 129，停在熟人，进不了很熟，所以大部分好友永远收不到信。
性别上限管的是她对人有多亲近，这次不动它，只放宽写信的门槛。

## 这次要改的两点

1. **写信门槛从"很熟"放宽到"熟人及以上"**
2. **每天收到信的概率按档位分**：熟人 0.08，很熟 0.25

（信的语气按档位区分这一点，这次先不做。）

## 具体改动

### ① `config.py`：概率改成按档位取值

```python
# 改前
letter_daily_prob: float = 0.25       # 每个符合条件的人，每天收到信的概率
# 改后
letter_daily_prob: dict[str, float] = {"acquaintance": 0.08, "close": 0.25}   # 每个符合条件的人每天收到信的概率，按关系分；表里没有的档位（陌生人、普通朋友、讨厌）不写信
```

- 写法和 `NUDGE_PROB`、`SKIP_FILLER_PROB` 一样，都用 `tier_value()` 取值，缺的档位按 0 算。
- 门槛直接由这张表决定：以后想让普通朋友也能收信，只要在 `.env` 里加一个 `friend` 的值，不用再改代码。
- `.env` 目前没有设置 `LETTER_DAILY_PROB`，改类型不会冲突。以后如果有人按老写法填一个数字，比如 `0.25`，会读取失败，所以要在参数文档里写清楚新写法。

### ② `__init__.py`：`_letter_prob_per_check()` 接收每天的概率作为参数

```python
def _letter_prob_per_check(daily: float) -> float:
    """把“每天的概率”折算成每次检查的概率（只在可寄信的时段里检查）"""
    window = sum(b - a for a, b in peak.parse_ranges(cfg.letter_hours)) * 60 or 86400
    checks = max(1.0, window / max(60, cfg.letter_check_interval))
    return 1 - (1 - min(max(daily, 0.0), 0.999)) ** (1 / checks)
```

### ③ `__init__.py`：`letter_blocker()` 的门槛

```python
# 改前
if familiarity_of(qq) != "close":
    return "还没到很熟"
# 改后
if tier_value(cfg.letter_daily_prob, familiarity_of(qq), 0.0) <= 0:
    return "还没到熟人"
```

### ④ `__init__.py`：`check_letters()` 按每个人的档位掷概率，很熟的人排在前面

```python
candidates = [qq for qq in set(ltm.user_ids()) | set(cfg.close_friends) if letter_blocker(qq, friends) is None]
random.shuffle(candidates)
candidates.sort(key=lambda q: familiarity_of(q) != "close")    # 很熟的排前面（同档位内保持随机）
sent = 0
for qq in candidates:
    if _letters_sent.get(today, 0) >= cfg.letter_max_per_day:
        break
    p = _letter_prob_per_check(tier_value(cfg.letter_daily_prob, familiarity_of(qq), 0.0))
    if random.random() < p and await write_letter(bot, qq):
        ...
```

为什么很熟的人要排前面：熟人放进来以后候选人会变多，每天全体最多 3 封的额度更容易用完。如果按完全随机的顺序处理，很熟的人可能被熟人挤掉。

### ⑤ `__init__.py`：`/写信 检查` 的名单

现在的名单只列出很熟的人（`familiarity_of(qq) == "close"`），改成列出概率大于 0 的档位里的所有人，并在每个人后面标上档位：

```python
close = [qq for qq in sorted(set(ltm.user_ids()) | set(cfg.close_friends))
         if tier_value(cfg.letter_daily_prob, familiarity_of(qq), 0.0) > 0]
# 空名单提示改成：“（现在还没有熟人以上的人，不会自动写信）”
# 每行加上档位：· 名字（QQ｜熟人）：……
```

## 不变的部分

每天全体最多 3 封、同一个人两封信至少隔 3 天、对方至少 24 小时没来找她才写、上一封没回就不再写、只在 10:00～22:00 寄且避开高峰、深夜不写。这些都照旧。

## 预期效果

- 熟人：满足条件时，平均大约 12 天收到一封。实际会更少，因为还要满足"沉默 24 小时""上一封已回"这些条件。
- 很熟：和现在一样，平均约 4 天一封。
