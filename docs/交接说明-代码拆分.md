## 2. 程序测试怎么跑

- 测试文件在 `bot\tests\`：`test_chat.py`（178 个）、`conftest.py`、`pytest.ini`。这是 9/30 01:25 第一次放到你们电脑上，之前只在聊天 agent 的云端环境里。
- **只用 `bot\程序测试.bat` 跑，不要在 `bot` 目录里直接 `pytest`**：测试会往 `data\` 下写聊天记录、记忆、花费账本，还会删掉 `data\usage`（每个测试前清空花费账本）。`程序测试.bat` 会把 `plugins`、`personas`、`knowledge` 和测试文件拷到 `%TEMP%\qqbot_pytest\` 再跑，不碰真的 `data`。
- 第一次跑会自动给 `.venv` 装 `nonebug 0.4.4`、`pytest 9.1.1`、`pytest-asyncio 1.4.0`。
- 这些测试一直是在 Linux 上跑的，**在 Windows 上还没跑过**。第一次如果有失败，先看是不是路径、换行、编码这类平台差异，不一定是代码的问题。
- 测试不调 DeepSeek（用假的模型回复），不花钱，20 秒左右跑完。

## 3. 测试和代码怎么对应

- 测试用 `import plugins.roleplay_chat as p`，通过 `p.某某` 调函数、改状态。
- 149 处 `monkeypatch.setattr(p.cfg / p.random / p.peak / p.spend ..., ...)` 改的是对象的属性，函数挪到新文件后不受影响。
- **38 处 `monkeypatch.setattr(p, "函数名", ...)` 要跟着改**：函数挪到新文件后，要替换新文件里的那个（比如 `monkeypatch.setattr(sleep, "asleep", ...)`），否则替换的只是 `__init__` 里的别名，被测代码还在用原来的，测试会“假通过”或者莫名失败。最多的是 `in_peak`（9 处）、`_in_hours`（9 处）。
- 还有几处直接赋值：`p._quiet_until = ...`、`p._kb = ...`、`p._heartbeat_task = ...`、`p._sticker_loop = ...`，以及 `conftest.py` 里每个测试前清空的一串状态（`p._private_hour`、`p._away`、`p._wrapup`……）。这些状态挪走后，`conftest.py` 要改成清新位置上的那一份。
- 别人改了功能，测试也可能要跟着改。今晚的例子：识图模块 22:35 起会先用 PIL 读图、需要时缩小，测试里原来用的假 PNG 字节就读不了了，4 个识图测试失败，已经改成生成一张真的 2×2 PNG。

## 4. 别的会被拆分影响的地方

- **`tools\regression.py`（回归测试）**：从 `__init__.py` 源码里直接取 `CHAT_RULES`、`FAMILIARITY_HINT`、`SHORT_VARIANTS`、`LENGTH_HINT`、`RECALL_RULES`、`LATE_HINT` 和 4 条收尾 / 休息提示（不 import，免得启动机器人），还会检查 `__init__` 里有没有 `echocheck`。挪到 `prompts.py` 以后要改成读新文件；**旧的备份 `docs\人设打磨备份\__init__.0929x.py.bak` 也还要能读**（回归测试拿它当“改前”），所以两种都要支持。
- **`qzone_diary.py`** 从 `__init__` 导入 20 多个名字（`cfg`、`client`、`clean_reply`、`FAMILIARITY_HINT`、`rate_limited`、`_locks`……），所以必须放在 `__init__` 最后导入。拆分时 `__init__` 要把挪走的名字再导出一遍，保证这些导入不断。
- **`stickers.py`、`vision.py`、`memory.py`** 也被主文件用到，拆分方案里没打算动它们。

## 5. 和另外两个 agent 怎么配合

- **人设 agent** 改 `bot\personas\elaina.md`，也常常要改 `__init__.py` 里的提示词（`FAMILIARITY_HINT`、聊天规则）。拆分开始前请用户告诉他：拆分期间先别改 `__init__.py`；拆完以后提示词都在 `prompts.py`，只改那一个文件。他和聊天 agent 的往来都记在 `docs\整理草稿\人设交接说明.md`（现在到第 22 节）。
- **别的 agent 也会改同一批文件**（今晚就有别人改了 `qzone.py`、`qzone_diary.py`、`vision.py`）。写回任何文件之前，先看一下它在电脑上的修改时间有没有变；变了就先重新读一遍、把对方的改动合进来，不要直接覆盖。
- 每拆完一步，在 `docs\版本说明与管理员指令.md` 里记一行（时间、挪了什么、测试结果）。
