## 给聊天 agent

> 语音 agent 看过《提示词审计-1022.md》4.9 节，人设“传声魔法”后半可以缩。以下是 `prompts.py`、`voice_chat.py` 要跟着改的地方，改完请跑测试（见最后）。
>
> **1. `VOICE_OFFER_HINT` 改三处**（`VOICE_REQUEST_HINT` 是老的认关键词办法，默认不用，顺手同步也行）：
> - 推掉的理由例子里删掉“懒得费魔力”，换成“嫌麻烦”。人设要她别总拿魔力当理由，提示里却拿魔力当例子，等于往回拉。
> - “后面照常写你要说的话”改成“后面写你要说的一两句短话”。现在传声要先译成日语再念，太长会变慢，超过 120 字直接改发文字。人设缩短后可能不再写“一两句”，所以挪到这里。
> - 补半句：“写了「[传声]」就是答应了，后面别再说不给。”出处是《传声人设测试报告-1020.md》V05：她写了「[传声]」，后面又说“魔力得省着点用”，结果是用声音说“不给”。如果人设缩完还保留这句，这里就不用加，两边留一处就行，跟人设 agent 对一下。
>
> **2. 新加：语音服务用不了时，告诉她这一轮传不了**（用户要的）
> - 现在的情况：`voice_roll()` 在 `tts_ready()` 为假（电脑上的语音服务没开、隧道断了）或当天 `VOICE_DAILY_MAX` 用完时，返回空提示。她不知道自己传不了，对方要语音时，常会用文字回一句答应的话（“好吧，听好了——……”），结果没有语音，很出戏。写了「[传声]」也只是被去掉标记、照常发文字。
> - 改法：`cfg.voice_enabled` 开着、`tts.configured` 为真、这一轮却用不了时，给一段新的提示（比如 `VOICE_UNAVAILABLE_HINT`），讨厌的人照旧不给。大意：
>   “【传声】这一轮你用不了传声魔法。对方想听你的声音时，用文字推掉，理由按你的性格和你们熟不熟来，每次换着说，别总说魔力；不要写「[传声]」，也别嘴上答应。”
>   别写成固定的理由（比如“魔力不够”），她会照抄。
> - 每轮都给（建议，和在线时一样由她判断对方是不是在要，“再来一条”也认得出；电脑关着时每轮多约 60 token），还是只在 `VOICE_REQUEST_RE` 认出关键词时给（省钱，但漏掉不带“语音 / 声音”的说法），请用户定。语音 agent 建议每轮都给。
> - 两种用不了（服务没开 / 当天额度用完）可以用同一段，她不需要知道是哪种。
>
> **3. 测试**：改完和人设缩短一起跑 `bot\传声测试.bat`，再加一组“用不了”的题：同样的 V01～V08（该发的），本轮提示换成上面那段，每题 5～10 次。看：
> - 在线组：V11～V16 不该发的有没有误发（以前 60 次里 1～2 次）；V05 写了「[传声]」后面有没有又说不给；陌生人是不是多半婉拒；答应时开头还是不是“就这一次 / 就这一句”（上次 22/48）；推掉时说魔力的比例。
> - 用不了组：有没有写「[传声]」，有没有嘴上答应，推掉的理由是不是总说魔力。
>
> 改了代码记得记《版本说明》、请部署 agent 部署。

## 给人设 agent

> 语音 agent 回复你缩“传声魔法”后半的问题：
>
> **① 缩成四点可以**。“本轮末尾的提示不代表对方在要”“没这个意思就别写”每轮【传声】提示里有，删掉没问题。语音这边测试专门要的有两句：
> - **“写了「[传声]」就是答应了，后面别再说不给、要省魔力”要留**（V05 测出来的）。你列的第一点“别再声明只此一次 / 费魔力”管的是答应时的口头禅，管不到“答应了又反悔”。留在人设里，或者让聊天 agent 挪进每轮提示，二选一，跟它对一下。
> - **“一两句短话”**：人设不留的话，聊天 agent 会加进提示。
> - “不要在文字里说‘我用传声魔法说给你听’”程序清不掉，不过线上没见过，删了问题不大。
> - “陌生人多半婉拒”和提示里的倾向句重复，可以先留着，测完再删。
>
> **② 每轮【传声】提示的改动交给聊天 agent 了**（见《交接-传声提示-语音这边-1022.md》）：删掉提示里的“懒得费魔力”，补“一两句短话”，加一段“语音服务没开时这一轮传不了，用文字推掉”的提示。
>
> 另外人设里可以补半句，不是必须：传声魔法有时用不了（太累、不方便），这时别人要也只能文字推掉。这样“用不了”的提示有个说得通的由头。
>
> 改完和聊天 agent 的改动一起跑 `bot\传声测试.bat`。
